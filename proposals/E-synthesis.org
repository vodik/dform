* 1. Position

dform is a stratified Datalog. The engine has exactly two non-monotone
operators, negation and aggregation, and both are placed by one dependency
graph. That is direction A's spine and it is kept whole: declared relations,
undefined predicate is a compile error, semi-naive evaluation over an operator
IR whose operators have DBSP counterparts, A's four lattices (Flat, Map, Set,
Keyed; no Bag), A's grammar.

Three things are grafted onto that spine, each restricted to the smallest
form that earns its place.

From B, *ranked cells*: a Flat attribute has three ranks, =@default=, normal,
=@override=. The highest rank with a witness wins; two witnesses at one rank
that disagree are the lattice top, never last-wins; schema refinements are
rank-blind constraints that every rank must satisfy. This replaces A's
=arg_default= with one mechanism that also covers environment layering and
the "prod forces deletion protection on" case A's candid section admitted it
could not express. Sets, maps and keyed lists are not ranked.

From C, *classed nulls*: =ref(T, A, Attr)= to a computed attribute is a
labeled null whose class comes from the schema. =fresh= (an identity) obeys
the Unique Name Assumption and decides equality at plan time; =open= (an
endpoint, an allocated range, a zone list) makes comparisons unknown; =secret=
is open and never materialized outside a provider call. A rule that needs
the content of an open null is *stuck*; stuck instances are recorded, not
derived; the plan has definite, pending and undetermined sections; apply
resolves nulls phase by phase and re-derives. C's chase, EGDs, user-written
=some= and =choose= are rejected: the only existential is the schema's
computed-attribute rule, and §2.7 shows why that fragment needs no
termination theory. C's absorptive provenance circuit replaces A's derivation
DAG; its seven homomorphisms are the whole of =why=, ownership, secrecy
labels, trust, cost attribution and phase ordering.

From D, *the plan as a Z-set*: =deformation = desired − world= in Z-set
arithmetic, computable on the naive engine today. A conflict derives a =deny=
and drops the address from =desired= instead of aborting evaluation. Apply is
a loop of ticks until the stack is undeformed, bounded by =--max-ticks=. D's
type partitioning of =arg=/=attr= is taken and, after working seam 3,
refined to (type, normalized path). D's log-as-truth, its =}= without a
period, and =Subscribe=/=Watch= as v1 protocol requirements are rejected.

Deferred: the DBSP circuit compiler (the IR is shaped for it; build it when
reactive mode is next) and clingo (a greedy =allocate= aggregate with pins in
state ships first; clingo goes behind a feature flag later).

The three seams the coordinator asked about, in one line each. Seam 1 (ranks
versus nulls): the coordinator's rule "collapse is undefined while any rank
holds an open null" is *replaced* by "rank decides first, then class": a
null at a losing rank never blocks, a same-rank disagreement involving an
open null is a new lattice element =Stuck= that resolution turns into a value
or a conflict, a secret in a same-rank disagreement is a conflict
immediately, and fresh nulls compete by rank like any value. Seam 2
(provenance under retraction): resolution is substitution plus one world leaf
per touched derivation; the invalidation set is exactly the =touches=
homomorphism, which is *not* C's =phase= instance (C's semiring was wrong for
the definite question; §3.4); v1 re-derives the strata downstream of a
retraction from scratch, and the bound is (phases + 1) full evaluations. Seam
3 (the aggregate): A's path normalization, D's type partitioning and B's
schema refinements compose into one aggregate definition, provided D's
partitioning is on (type, normalized path) rather than type alone, and
provided "schema rank" is read as "rank-blind constraint component"; both are
small overrides of the brief with a concrete example each.

What this direction costs, stated once: provenance is always on (2 to 4
times the bare fact store); the plan has phases and a third policy outcome,
which is a bigger mental model than Terraform's refusal; and two of the
grafts (=Stuck=, the resolution-time re-derivation) are new machinery that no
production Datalog has run at scale. §10 says where it is most likely wrong.

** 2.2 Null classes

A labeled null is a value known to exist, unique under its label, whose
constant the engine does not have yet. Labels are Skolem names,
="type/addr#attr"=, deterministic across runs so a plan file is stable.

The class is assigned by the schema, never by the user:

| Schema flags on =type_attr(T, P, Ty, Flags)= | Class    | Examples                                  |
|-----------------------------------------------+----------+-------------------------------------------|
| =computed= and =id= (or =computed fresh=)     | =fresh=  | id, arn, self_link, uid                   |
| =computed=, not sensitive                     | =open=   | endpoint, allocated cidr, zones, ca cert  |
| =computed= and =sensitive=; =secret= inputs; =-secret(T)= extern columns | =secret= | password, access token, private key |

The class drives three things.

*Equality* (=eq3=, three-valued, implemented and tested):

| =a=                | =b=                        | =eq3(a, b)= |
|--------------------+----------------------------+-------------|
| null, label =l=    | null, label =l=            | True        |
| fresh null         | any constant               | False       |
| fresh null         | fresh null, other label    | False       |
| fresh null         | open or secret null        | Unknown     |
| open or secret     | anything with another label | Unknown    |
| list / object      | list / object              | positional / keywise fold: any False is False, else any Unknown is Unknown |

The Unique Name Assumption on =fresh= is a true statement about every cloud
API dform targets: a resource not yet created has an id equal to nothing that
exists. It is what makes =not attr(T, X, .id, ν)= and =ν != "vpc-1"= decidable at
plan time and it is why the peering example in =dform.df= plans in one phase.
=open= nulls carry the honesty: the engine does not pretend to know whether a
to-be-allocated endpoint equals a string.

*Materialization*: a =fresh= or =open= null is substituted by its constant at a
phase boundary (§2.7). A =secret= null is never substituted in the fact
store; the provider resolves it inside the =Apply= call from the store the
label names. Printing, plan files and state see the label only. A rule that
would need a secret's content is a compile error from A's static label pass
(E0301..E0305), not a runtime stuck, because the schema makes the position
statically =secret=.

*Phase*: which null a fact carries or is stuck on decides when its
deformation can be applied. §2.7 and §3.4.

*Override.* The brief says "class drives equality (fresh by label, open/secret
unknown)". Kept, with one precision the cases forced: =fresh= versus a
*constant* is =False=, not "by label". Without it, =arg(sub, S, .vpc_id, ν)=
against a hand-written ="vpc-1"= at the same rank would be stuck, and the
adopt workflow would wait for an apply that never comes.

** 2.3 The lattices

A's four constructors, with one new element.

- =Flat(D)=: =⊥ < d < ⊤=, distinct =d= incomparable. Join: =d ⊔ d = d=,
  =d ⊔ d' = ⊤=.
- =Map(K, L)=: finite partial functions, pointwise join, absent key is =⊥=.
- =Set(D)=: finite subsets, union, no =⊤=.
- =Keyed(K̄, L)=: =Map= over the projection of each element onto the merge
  keys; emitted as a list in key order.

There is no =Bag=. Multiset union is not idempotent; a rule that fires twice
with the same binding would double its contribution, which is the order
dependence this design exists to kill. =collect_list= survives as an
aggregate *inside one rule* whose result is one =Flat= contribution.

The new element is =Stuck=. With nulls in the value domain, =d ⊔ d'= has a
third outcome: =eq3(d, d') = Unknown=. Then the join is neither =d= nor =⊤=;
it is =Stuck(S)= where =S= is the set of pairwise-undecided contributions,
together with the labels of the nulls whose resolution will decide it.

Precise definition, as implemented. Every non-=⊥= element is the *normal form
of its full contribution list*; join is concatenation followed by
normalization. For =Flat=:

1. merge contributions that are =eq3=-True (witnesses union), sort by value;
2. if one remains: =Val(v, W)=;
3. if any pair is =eq3=-False: =Conflict=, carrying *every* contribution and
   naming the least unequal pair for the diagnostic;
4. if any pair involves a =secret= null: =Conflict= ("a secret cannot be
   compared with another contribution"), because the engine will never be
   able to decide it and stuck-forever is worse than a conflict now;
5. otherwise: =Stuck(S, nulls(S))=.

=Map= and =Keyed= normalize per key with the element lattice; a =Stuck= leaf
makes the container =Stuck= (the engine keeps the other keys' values and
marks the leaf; the prototype drops them, noted in §9). =Set= never conflicts
and is never stuck: two elements that *might* be equal are both kept until a
null resolves, and the provider receives both. Keyed lists whose merge key
contains an open null keep such elements in separate groups until resolution
and the compiler warns on the pattern.

Laws, all tested under every permutation (Heap's algorithm) and under
duplication of every contribution: commutative, associative, idempotent, for
each constructor, over samples mixing constants, fresh, open and secret
nulls. Two laws failed on the first run and forced the "normal form of the
full list" definition: a =Conflict= that kept only the first offending pair was
not associative in its witness set ((a ⊔ b) ⊔ f named {1,2}, a ⊔ (b ⊔ f) named
{2,3}), and a =Map= =Stuck= that stored its two inputs in arrival order was
not commutative. Both are the same mistake, an element that remembers *how*
it was built, and the fix is that no element does. This is also why the
engine's conflict diagnostic can name every contributor (D's =⊤(owners)=), not
just two.

** 2.4 Ranked cells

A ranked cell is a Flat cell with three slots and a constraint set:

#+begin_src rust
struct Ranked { ranks: [Elem; 3], constraints: BTreeMap<Constraint, Witnesses> }
enum Rank { Default = 0, Normal = 1, Override = 2 }
#+end_src

Join is pointwise on the three slots (Flat join) and union on the
constraints, so it inherits the laws. *Only Flat attributes are ranked.* A
=Set= path unions across every author; a =Map= or =Keyed= path is ranked at its
leaves, because its leaves are Flat cells. "Replace the whole set in prod" is
not expressible and that is deliberate (A's DR-1 reasoning stands; B's =seal=
is not taken).

Exactly three ranks. B had four and a =rank= declaration; the fourth
(=force=, for the operator) is the CLI's =--set=, which populates *inputs*, and
inputs are declared relations no source rule may write, so they never
conflict with anything. Three named ranks with no numbers is the whole of the
"who gets 900" social problem B admitted, made smaller.

Syntax: =@default= or =@override= after a value (=deletion_protection = true
@override=), or after a block header to apply to every leaf in the block
(=settings E @default { ... }=). No annotation is normal. =input k: T = v=
lowers to a =@default= contribution. Core form: =arg(T, A, P, V, R)= with
=R ∈ {default, normal, override}=.

*Collapse*, the one non-monotone read, in the order the prototype does it:

1. if any rank is =Conflict=: =Conflict= (a shadowed disagreement is still a
   disagreement; hiding it because a third author out-ranked both is what
   last-wins systems do);
2. if any rank is =Stuck=: =Stuck= on that rank's nulls (the same reason; it
   will become one of the two outcomes above);
3. the highest non-=⊥= rank's value =v= wins;
4. every constraint is checked against =v=: =False= is =Conflict= naming the
   constraint's schema witness and =v='s witnesses; =Unknown= (=v= carries a
   null) is *deferred* and re-checked at resolution; a =secret= =v= defers
   every constraint to the provider.

Constraints are rank-blind. *Override* of the brief's phrase "joined in at
schema rank": a constraint that could be out-ranked is not a constraint.
B's own collapse conjoins constraints across all ranks, so this is B's
semantics with the misleading name removed, and it is what makes an
=@override 30= against a =<= 20= a conflict (tested).

Collapse is a stratum boundary: =attr= is an aggregate head, so every reader
of =attr= is strictly above every writer of =arg= for that partition (§2.6).
Nothing else in the engine is non-monotone.

** 2.5 The aggregate, one definition

For every schema-declared attribute path =P= of type =T=, the compiler emits
one aggregate. Three proposals touched this aggregate (A's path
normalization, D's type partitioning, B's schema refinements). They compose
into one definition; §4.3 is the argument, this is the result.

#+begin_src prolog
% Prelude, compiler-generated. Sources of contributions:
contrib(T, A, P, cell(R, V))      :- arg(T, A, P0, V0, R), normalize(T, P0, V0, P, V).
contrib(T, A, P, constraint(C))   :- want(T, A), type_refine(T, P, C).
contrib(T, A, P, cell(normal, N)) :- want(T, A), type_attr(T, P, Ty, Flags),
                                     member(Flags, computed), N = null(T, A, P, class(Flags), Ty).

% The aggregate. `lub_ranked` folds cells with the ranked join and finalizes with collapse.
attr(T, A, P, lub_ranked(X))      :- contrib(T, A, P, X).

% What collapse can produce, as facts the rest of the program reads:
%   attr(T, A, P, V)                  a value (V may carry nulls)
%   attr_conflict(T, A, P, W1, W2)    top, with two witness fact ids (every witness is in provenance)
%   attr_stuck(T, A, P, Nulls)        a same-rank disagreement waiting on Nulls
#+end_src

- =normalize/5= is A's path normalization done *at compile time when the path
  is a constant*: a head =arg(T, A, .tags.team, V)= is rewritten to
  =arg(T, A, .tags, {team: V})= before the dependency graph is built, so all
  contributions to one declared attribute meet in one group. A variable path
  normalizes at runtime and its rule sits in the =(arg, T, *)= partition.
- =type_refine/3= is the schema's checkable refinements (type tag, interval,
  =prefix_len=, enum, regex), as EDB. They enter the cell as constraint
  contributions. Refinements not in the checkable table lower to =deny= (DR-14).
- The third rule is the *only existential in the language*: the computed
  attribute's null, minted once per =(T, A, P)=. It is a contribution at rank
  normal like any other; users cannot write a value for a computed path (a
  compile error from the schema), so nothing ever competes with it by rank.
  Its resolution is substitution (§2.7), not a rank.
- =output(Instance, Key, V)= and =setting(Env, Path, V)= are the same aggregate
  over the pseudo-types =output= and =settings= (A's decision, kept).

The aggregate group is =(T, A, P)= with =P= the normalized path. Its stratum
node is =(attr, T, P)= (§2.6).

** 2.6 Predicate kinds and the stratification graph

Every predicate is exactly one of: *extensional* (ground facts in source,
extern results, world facts, schema facts, inputs), *intensional* (rules), or
*aggregate* (rules whose head has exactly one aggregate term; =attr= is one).
A predicate that is both EDB and IDB is a compile error unless declared
=decl p/N mixed.= (A). A body predicate with no definition is a compile error;
=extern= declares provider-fed ones. Module-private predicates, =export=,
=input=/=output=, =contributes=: A's module system, unchanged (DR-3).

The dependency graph has one node per predicate, except =arg= and =attr=,
which have one node per *partition* =(pred, T, P)= where =T= and =P= are the
head's type and normalized path when constant and =*= when not. Two
partitions are connected iff they unify. An edge runs from each body
predicate (or partition) to the head. An edge is *negative* if:

- the body literal is under =not=;
- the head is an aggregate predicate (every reader of an aggregate is above
  its whole group: the fix for the "aggregates are not stratified" repro);
- the body literal is an extern (evaluated once per stratum after its bound
  inputs are complete);
- the body literal is =attr=, =output=, =setting=, =attr_conflict= or
  =attr_stuck= (aggregates; listed for the reader).

A cycle through a negative edge is a compile error naming the cycle with
=file:line= per edge. Stratum = longest negative-edge path. Within a stratum,
semi-naive evaluation over the operator IR, no iteration cap. Externs may not
be under =not= and may not be in a cycle. =provider_config/2= may depend on
nulls (that is what makes a provider phase-2, §2.7) but may not depend on an
extern of its own provider; that cycle is reported.

Why partitions and not whole predicates: with one =attr= node, the network
module (=arg(net.subnet, ...)= reads =attr(net.vpc, vpc, .cidr, V)=) is a
negative self-loop. With D's type-only partitions it compiles, but A's own
baseline example (=arg(iam.policy, A, .statements, ...) :- attr(iam.policy, A,
.name, "app")=) is a self-loop on =(iam.policy)=. With =(type, path)=
partitions both compile and the tag policy =arg(T, A, .tags, ...) :- want(T,
A)= lands in =(arg, *, .tags)=, above every reader of =.tags= and nothing
else. The =contributes arg to TypePat at PathPat= grant is that partition
pattern spelled by the author, and a head outside its grant is a compile
error. This is the narrowest form of B's partitioned stratification: two
compiler-owned predicates, two columns, constants only. B's general
=partition= declaration on user relations stays rejected.

The operator IR is A's: =Scan=, =Join=, =AntiJoin=, =Filter=, =Map=, =Extern=,
=Distinct=, =Agg=, =Fix=, plus one new operator, =Stuck=, which is =Filter='s
third output (§2.7). Every operator has a DBSP counterpart; =Stuck= is a
=Filter= with two output streams.

** 2.7 Phases

The whole apparatus of C, reduced to four rules.

*Rule 1, carrying.* A null may appear inside any tuple. A fact whose tuple
carries a null is an ordinary fact: it joins, projects, unifies by label, and
is forwarded into attribute values (=vpc_id = ref(net.vpc, vpc, .id)=). The
plan shows it with its label.

*Rule 2, stuck.* A literal that needs a null's *content* does not fire. The
content positions are: an operand of =<=, =<==, =>=, =>==; either side of === or
=!== when =eq3= is Unknown; any builtin argument (=format=, =inet_subnet=,
=len=, =member= over a null list); an aggregate's group key or aggregated
value; and any argument of a resource *address*. When the literal's
=eq3=/builtin evaluation returns Unknown, the rule instance is recorded as
=stuck(RuleId, Bindings, Nulls)= (D's companion relation, generated by the
compiler for every rule with a content position) and nothing else is
derived. Negation and equality over =fresh= nulls are decided under UNA and
never stuck.

*Rule 3, undetermined.* =not p(t̄)= is decided against the current =p= *only if*
no stuck instance exists for any rule whose head is =p=; otherwise the
negating instance is stuck on the union of those instances' nulls. An
aggregate over =p= is likewise undetermined, and its readers stuck, while any
=p=-rule instance is stuck. This is predicate-coarse and deliberately so: it
is what makes the definite fragment *monotone across phases* (§4.2), and it
is checkable in one pass over =stuck/3=. A =deny= that is stuck is reported as
*undetermined*.

*Rule 4, resolution.* A phase boundary is the prelude rule

#+begin_src prolog
resolve(N, V) :- null_of(T, A, P, N), identity(T, A, Rid), world_attr(T, Rid, P, V).
resolve(N, V) :- null_of(T, A, P, N), extern_result(T, A, P, V).       % allocate, random.*, file.*
#+end_src

evaluated after refresh (round 0: every resource that already exists has its
computed attributes resolved before the plan is printed, so a steady-state
stack has no nulls at all), after =adopt= (which is =identity/3= written by
the user), and after each apply phase. A resolution substitutes =N := V= in
every tuple carrying =N= (a =−1=/=+1= pair, same provenance node plus one
world leaf; §3.4), re-collapses every cell that carried =N= (which is where a
=Stuck= becomes a value or a conflict and a deferred refinement becomes a
conflict), and re-runs every stuck instance blocked on =N=. New facts flow
forward semi-naively; retractions are handled per §4.2. =secret= nulls are
never resolved in the store; =resolve/2= for them is a provider-side
operation and the fact store keeps the label.

*Phase assignment.* A phase is a *re-evaluation boundary*, nothing else. A
deformation for address =(T, A)= is *definite* when its =desired= row exists
(no rule on its path is stuck) and its cells are neither =Stuck= nor
carrying a deferred constraint. A definite deformation's document may carry
nulls: the executor substitutes them at apply time from resolutions earlier
in the dependency DAG, which is Terraform's ordinary behaviour and needs no
re-evaluation (a subnet's =vpc_id= is a fresh null until the VPC's =Apply=
returns, seconds earlier). Let =blocking= be the union of the nulls named by
=stuck/3=, by =attr_stuck=, and by deferred constraints. After any action
that resolves a null in =blocking=, the executor inserts a boundary: it
feeds the results back as =world_attr= and =identity=, runs the resolution,
re-derives, re-checks policy, and only then continues. Every deformation
*downstream in the DAG* of such an action is held until the boundary
completes and is printed as pending on those nulls. Deformations that are
not downstream proceed in the same phase. A deformation whose row does not
exist yet (a stuck instance) is pending on its nulls by construction.
Provider configuration carrying a null is configured lazily after the null
resolves; it forces a boundary only if the null is in =blocking=, but in
C's example it is (the cluster's creation also resolves =zones=), so the
kubernetes objects land in phase 2 and the executor re-checks policy before
touching them. A stack is *undeformed* when =deformation= is the zero Z-set,
=stuck/3= is empty and no cell is =Stuck=. =--max-ticks= bounds the loop.

*Why no chase termination theory is needed.* The only existential is the
computed-attribute prelude rule in §2.5. Its frontier is =(T, A, P)=, all
bound in the body; its null is a Skolem function of the frontier; it fires
at most once per =(want(T, A), computed P)=. It could cascade only if a null
could reach a *frontier* position of that rule, i.e. an argument of =want/2=
or the schema facts. The schema is EDB. =want/2='s second argument is a
resource address, and address arguments are content positions (Rule 2), so
an instance that would put a null into an address is stuck, not fired; after
resolution the address is a constant. Hence, in the position graph of Fagin
et al., the only special edges go from =want= positions into =attr='s value
position, and no path leads from any null-bearing position back to a =want=
position: the program is trivially weakly acyclic, the "chase" is one round
per phase, and the number of nulls is bounded by =|want| × |computed paths|=.
No user syntax can mint a null, so no user program can change this. C's two
acyclicity checks and Datalog-first firing order are not needed and not
implemented.

*C's worked example, re-run under these rules* (final syntax in §7.4):

1. =want(gke.cluster, pngu)= is definite. The prelude mints
   =ν_ep=, =ν_ca=, =ν_zones= (=open=), =ν_id= (=fresh=), and
   =ν_tok= (=secret=, from =google.client_config=).
2. =provider_config(kubernetes, {host: ν_ep, ca: ν_ca, token: ν_tok})= is a
   definite fact that carries three nulls (Rule 1). Its phase set is
   ={ν_ep, ν_ca, ν_tok}=.
3. =resource gke.nodepool Np { ... } :- attr(gke.cluster, pngu, .zones, Zs),
   member(Zs, Z), Np = format("np-%s", Z)=: =member= over an open null is a
   content position; the instance is stuck on ={ν_zones}= (Rule 2). The plan
   prints one pending group "gke.nodepool np-? × unknown, depends on
   ?gke.cluster/pngu#zones".
4. =k8s.namespace= and =k8s.deployment= are definite facts, but their provider
   config is pending on three nulls, so their *deformations* are pending on
   the same set. Their full diffs are shown now, which Terraform cannot do.
5. =zone_count(count(Z)) :- attr(gke.cluster, pngu, .zones, Zs), member(Zs, Z)=
   has a stuck instance, so the aggregate is undetermined (Rule 3) and
   =deny(two_zones, ...) :- ..., zone_count(N), N < 2= is stuck: the plan
   prints it as *undetermined*.
6. Apply phase 1 creates the cluster; refresh delivers =endpoint=, =zones=,
   =id=; the resolution substitutes them; the nodepool instances fire twice
   (two zones); =zone_count = 2=; the =deny= instance now evaluates =2 < 2= to
   false and derives nothing. Phase 2 has three definite deformations; the
   executor checks policy (no denies) and proceeds. Had =zones= come back with
   one element the =deny= would derive, the executor would stop between
   phases with the cluster created and the plan file would say so.

Nothing here is C's chase: it is nulls, stuck instances, substitution and
semi-naive re-derivation. The user wrote no phase and no =depends_on=.

** 2.8 The plan as a Z-set

D's definition, on the naive engine, today:

#+begin_src prolog
desired(T, A, Doc) :- want(T, A), not attr_conflict(T, A, _, _, _), not attr_stuck(T, A, _, _),
                      Doc = assemble(T, A).                    % aggregate over attr(T, A, _, _)
world(T, A, Doc)   :- identity(T, A, Rid), world_doc(T, Rid, Doc).   % refresh, keyed by state's mapping
% deformation is the one native operator: diff = desired − world as Z-sets over (T, A, Doc)

Per address the group in =diff= is ={+1}= create, ={−1}= delete, ={+1, −1}=
update (the provider's =Plan= RPC decides replace), empty means undeformed.
=lifecycle/3= facts are filters and policy over =deformation/5=;
=ignore_changes= paths are dropped from both sides by =assemble=. Adoption
rewrites the world address before subtraction. A create whose =Doc= carries a
null is still a create; the executor fills the null in dependency order
(§2.7). An update whose desired =Doc= carries a null that the world side has
a constant for is *pending*: the comparison is a content position and it is
decided at the next boundary. Round-0 resolution means a steady-state stack
never has the second case.

Conflict is a fact, not an abort: the prelude carries
=deny(attr_conflict, "conflicting attribute contributions", {type: T, addr:
A, path: P}) :- attr_conflict(T, A, P, _, _).= and =desired= excludes the
address, so nothing downstream of a =⊤= deforms anything. Same for =Stuck=:
=warn(attr_stuck, ...)= at plan time, and the address waits.

=state.json= stays the identity mapping =(T, A) → Rid= plus persisted extern
results (DR-7); it is the *only* thing dform writes that it later trusts.
The append-only log of ticks (inputs, extern responses, apply results) is an
audit artifact beside it: =dform log= reads it, =--as-of= replays it, nothing
in plan or apply reads it as truth. *Override* of D's log-as-truth, with D's
own reason: the log holds observations of a world it does not own, and a
retention policy should never be able to break =plan=.

Apply: write the plan file (the tick's inputs, extern responses, and the
deformation delta with its =why= digest); apply consumes the plan and refuses
if re-evaluation does not reproduce the delta; persist =identity= after each
action; run ticks until undeformed or =--max-ticks=. Deletes in reverse
dependency order after the creates that replace them unless
=create_before_destroy=. This is the apply-executor ticket's content and it
does not change under any direction.

* 3. The provenance circuit and its seven instances

** 3.1 What is stored

C's absorptive circuit replaces A's per-fact derivation vector. The
difference matters: A's DAG keeps every derivation and prunes only by an
id-ordering trick; C's keeps an antichain of alternatives per fact under the
absorption law =a ⊕ (a ⊗ b) = a=, which is what makes the circuit finite for
recursive programs (Deutch, Milo, Roy, Tannen 2014, Thm. 3) and what makes
=why= output readable (no proof that is a superset of another proof).

Nodes, as prototyped:

| Node          | Meaning                                                                      |
|---------------+------------------------------------------------------------------------------|
| =Leaf=        | an indeterminate: base fact (span), rule (id), schema fact (span), world event (apply result, refresh row, extern call), absence =¬p(t̄)= (Grädel–Tannen dual) |
| =Fact=        | one tuple; holds its alternatives, an antichain of =Times= nodes             |
| =Times=       | one rule firing: the rule leaf, the body facts, absence leaves, and for an aggregate the =Σ= marker over the group |

A fact's =Plus= is its alternative list; there is no separate =Plus= node. Per
fact the store holds one =NodeId=; per firing one =Times=. Hash-consing of
=Times= nodes is by child set.

Absorption is applied *structurally* at each =⊕=: a new firing is dropped
when an existing alternative's leaf set is a subset of its own, and it evicts
alternatives whose leaf sets are supersets of its own. The prototype computes
leaf sets by walking; the engine keeps a per-=Times= leaf-set digest
(a 64-bit bloom is enough to say "not a subset" fast) and caps alternatives
at =k = 8= with a =truncated= flag, C's =--why-depth=. A missed absorption
costs size, never correctness: every instance below is a semiring
homomorphism evaluated by fold, and a redundant alternative contributes
nothing new to an absorptive target.

Negation: a negated literal that held contributes a leaf =¬p(t̄)= to the
firing. Because negation is stratified the negated predicate is complete
when evaluated, so the leaf is either fresh (absent) or the firing does not
happen. The =x ⊗ x̄ = 0= law is enforced structurally: a =Times= whose children
contain both =p(t̄)= and =¬p(t̄)= is pruned (it cannot arise in stratified
evaluation and the check is one set lookup).

Aggregation: an aggregate fact's single alternative is a =Times= over the
=Σ= marker and every contributing fact (Amsterdamer, Deutch, Tannen 2011,
specialised to un-annotated aggregate values). For the attribute aggregate
this means =attr(T, A, P, V)= carries every =arg= that reached the group and
every constraint that was checked, which is exactly what "who contributed
to this attribute" and "which schema line refused it" need.

** 3.2 The instances

Each is a homomorphism =h: Sorp[X] → K= given by its leaf valuation and its
treatment of absence leaves and =Σ=. All are lazy folds over the stored
circuit; none is stored separately except where noted.

| Instance      | =K=                                  | leaf valuation                              | =¬x=          | =Σ=             | consumer                                       |
|---------------+--------------------------------------+---------------------------------------------+---------------+-----------------+------------------------------------------------|
| why           | =Why[X]=: sets of leaf sets, ∪, pairwise ∪ | ={{x}}=                                | ={{¬x}}=      | ⊗ all members   | =dform why=, conflict printer                  |
| lineage       | =Lin[X]=: sets of leaves, ∪, ∪       | ={x}=                                       | ={¬x}=        | ∪               | =dform plan --explain=, =moved= proposals      |
| owner         | =P(Owner)=, ∪, ∪                     | owner of =x='s file / module instance / pack / provider | =∅= | ∪            | L1b field ownership, conflict messages, =managed_by= in state |
| trust         | total order of trust levels, min, max | trust of =x='s source (pack annotation, provider lock entry) | trust(x) | max | policy: "attribute in prod from an unreviewed pack" |
| label         | =public < secret=, min, max          | =secret= for sensitive schema paths, =secret= inputs, =-secret= extern columns; else =public= | label(x) | max | plan/state redaction; the runtime half of DR-20 |
| cost-attrib   | =(ℚ, min, +)= on price-fact leaves only | price if =x= is a =price/3= fact, else 0   | 0             | +               | =dform cost --by module=: attribution, not totals |
| phase         | =(P(N), ∩, ∪)=, identity =N=         | nulls in =x='s tuple                        | nulls in =p(t̄)= | ∪             | definite / pending / undetermined sections; executor ordering |
| touches       | =(P(N), ∪, ∪)=                        | nulls in =x='s tuple                        | nulls in =p(t̄)= | ∪             | invalidation at a phase boundary (§4.2)        |

That is eight rows for the brief's seven. *Override*: C's =phase= instance is
written as =(P(Nulls), ∪, ∪)=, and that semiring answers the wrong question.
A fact with two alternatives, one null-free and one through a null, is
*definite*: it will exist whatever the null resolves to. Under =(∪, ∪)= it
would be reported pending. The definite question is =⊕ = ∩= ("some
alternative needs none of these"), =⊗ = ∪= ("this alternative needs all of
these"); =(P(N), ∩, ∪, N, ∅)= is a commutative semiring (∪ distributes over
∩) and it is absorptive (=a ∩ (a ∪ b) = a=). The =(∪, ∪)= instance is still
needed, for the other question, "what may change when ν resolves", and that
is the seam-2 invalidation set. Both are implemented and the distinction is
tested: =phase_and_touches_before_resolution= shows a fact with one null-free
alternative has =phase = ∅= and =touches = {ν}=.

The =phase= instance adds the fact's *own* tuple's nulls on top of the fold
(a carried null is a dependence even if every alternative is null-free,
which cannot happen but is cheap to state). Absence leaves =¬p(t̄)= contribute
=nulls(t̄)=: a negation decided against a pattern that carried a null (only
possible for =fresh=, by Rule 2) depends on that null's identity being what
UNA said; no resolution can change it, so this is conservative, not needed
for correctness, and kept for symmetry.

Cost, honestly. Per fact: 8 bytes (node id, flags). Per firing: one =Times=
node, 24 bytes plus 4 per child, typical 40-60 bytes. A real account at 10^5
facts per stratum with an average of 2 firings per fact is 10-15 MB of
circuit. C's measured expectation of 2 to 4× over a bare store is the right
order; Soufflé's provenance mode is 1.5 to 3× with less per node. Time: the
absorption check per =⊕= on a fact that already has alternatives; with the
bloom digest it is a handful of word operations. Evaluation may take extra
semi-naive iterations to discover non-absorbed alternatives; bounded by =k=.
Provenance is always on. There is no =--no-provenance= because the conflict
printer, the ownership grant check, the secret redaction, the phase
assignment and =moved= all read it. That is the price and it is paid by
every plan.

** 3.4 =moved=

Hand-written =moved(T, From, To)= is primary: an EDB fact, applied by the
executor as an =identity= rewrite before the diff, so no destroy and no
create. Proposals are secondary and read the =lineage= instance: for each
=(−1, +1)= pair in the plan whose world document is a model of the new
address's =attr= bundle modulo nulls, and whose lineage under the program's
rename map equals the previous plan file's lineage for the old address,
=dform plan --suggest= prints a =moved/3= line. Plan files serialize the
circuit so the previous lineage is available. Nothing is applied without
the user pasting the fact in. General view update (drift reconciled into
source, =put= through rules) is rejected: the restricted single-witness,
value-preserving case A defined is the only one where an edit is unique, and
it is a CLI feature over =why=, not an engine feature.

* 4. The three seams

** 4.1 Seam 1: ranked cells against three-valued nulls

The brief's proposal: collapse is undefined while any rank holds an open
null; a read is stuck and resolves at the phase boundary; schema refinement
checks on null-carrying cells are deferred. Worked through six cases in the
prototype (tests =case1_= to =case4_= and =case2b_= in =src/lattice.rs=), every
case under every permutation of its contributions.

*** Case 1: fresh null and a concrete at different ranks

=vpc_id = ref(net.vpc, vpc, .id)= at normal (a fresh null, forwarded), and
=vpc_id = "vpc-existing" @override= (an operator pointing a subnet at a
pre-existing VPC).

Collapse: =@override= wins, value ="vpc-existing"=, no stuck. Under UNA the
null and the constant are definitely different, so this is an ordinary
override of one value by another. Reversed (the null at =@override=, ="vpc-old"=
at normal): the null wins and is forwarded; nothing is stuck; the subnet is
pending on =ν= exactly as if no override existed. Same rank: =Conflict= now,
because UNA decides it; likewise two fresh nulls with different labels at
one rank. Same label at one rank: agree, witnesses union.

Verdict: *fresh nulls are values and compete by rank*. The coordinator's
question "does a fresh null at =@override= beating a concrete at normal ever
make sense" has a concrete yes: =settings prod @override { db.subnet_ids =
[ref(net.subnet, private_a, .id)] }= replacing a =@default= list of hard-coded
ids from before the subnets were managed. A rank-blind null would make that
program a conflict. Rank-blind nulls are rejected.

*** Case 2: open null and a concrete at the same rank

=endpoint = ref(gke.cluster, pngu, .endpoint)= and =endpoint = "1.2.3.4"=, both
at normal. =eq3= is Unknown, so the rank's element is =Stuck({ν, "1.2.3.4"},
{ν})= and collapse returns =Stuck=. At resolution =ν := "1.2.3.4"= the cell
re-normalizes to =Val("1.2.3.4", {1, 2})=, both witnesses; =ν := "9.9.9.9"=
gives =Conflict= naming both. Three-way (open null, ="a"=, ="b"=) is a =Conflict=
immediately, because the two constants already disagree and no resolution
can change that; this is a case the "any rank holds an open null" rule
would have needlessly deferred.

Verdict: *confirmed*, with the sharper statement that stuck is a property
of the same-rank disagreement, not of the presence of a null.

*** Case 2b: open null at a losing rank

=endpoint = ref(...)= at normal, =endpoint = "1.2.3.4" @override=. The
coordinator's rule says undefined. Collapse under the rank rule: =@override=
wins; the lower rank's witness is irrelevant except for its existence;
result ="1.2.3.4"=, nothing deferred, nothing stuck. Reversed (null at
=@override=, constant at normal): the null wins, collapse is =Val(ν)=,
forwardable; content readers are stuck on =ν= by Rule 2, not by the cell.

Verdict: *the brief's rule is replaced*. "Collapse is undefined while any
rank holds an open null" is too strong by exactly the losing-rank case, and
that case is the common one: a =@default= from a module (often a computed
placeholder) overridden by the program. The rule is: *rank decides first,
then class*. =Conflict= or =Stuck= at any rank propagates (a disagreement is a
disagreement wherever it sits); a lone null at any rank is just a value.

*** Case 3: secret null anywhere

At the winning rank: collapse is =Val(secret ν)= with every constraint moved
to =deferred= and marked for the provider; the engine never checks a secret
against a refinement, A's rule for secret inputs generalized. In a same-rank
disagreement with anything (a constant, another secret with a different
label): =Conflict= immediately, reason "a secret value cannot be compared
with another contribution". Stuck-forever would be the alternative, and a
plan that never becomes definite is worse than a conflict the user can see;
the diagnostic prints both owners and neither value. At a losing rank: the
concrete wins; the collapsed witnesses exclude the secret's contributor (no
taint from a loser, because the result does not depend on it), but
=Ranked::all_witnesses= still includes it for =why=. The =label= instance
therefore reports the winning attribute as public, and the static pass
(E0304) has already refused to let a secret reach a non-sensitive path in
the first place, so this case can only arise on a =sensitive= path where
both answers are acceptable.

Verdict: *confirmed with one addition*: secret-in-disagreement is a
conflict, not a stuck.

*** Case 4: a refinement on a null-carrying cell that later violates

Schema: =master_control_plane_cidr: inet where prefix_len = 28=. Contribution:
an open null from an allocator at normal. Plan time: collapse is =Val(ν)=
with =deferred = [PrefixLen(28)]=; the plan prints the attribute as
=?alloc/cp#cidr (checked at apply: prefix_len = 28)=. Resolution to
=10.0.0.0/24=: =Conflict= naming the schema witness (the =type_refine= fact's
span) and the contributor's witness. Resolution to =172.16.3.96/28=: =Val=
with nothing deferred. An =@override 30= against =<= 20= is a conflict at
plan time, confirming constraints are rank-blind.

Then the engine's reaction, driven through the circuit in
=resolution_that_violates_a_refinement_retracts_the_cone_and_derives_a_conflict=:
the re-spelled =attr= row is retracted, its forwarding cone (a dashboard
attribute that copied it) goes with it, the =arg= contribution below the
aggregate survives, =attr_conflict= is derived with the schema leaf, the
contributor's rule leaf and the world event in its =why=, and it is definite.
The executor sees =deny(attr_conflict)= and stops between phases.

Verdict: *confirmed*. Deferred checks are the right behaviour and the
retraction they cause is the only retraction a phase boundary produces
(§4.2). Refinements that are not checkable at join (L13's cross-cell
predicates) lower to =deny= rules that are simply stuck until the null
resolves; the two homes never report the same violation twice because the
compiler assigns each refinement to exactly one (DR-14).

*** The rule, final

1. Join per rank is the Flat normal form of §2.3; constraints union.
2. Collapse: =Conflict= at any rank wins; else =Stuck= at any rank wins; else
   the highest non-empty rank's value under all constraints, with checks on
   null-carrying values deferred (secret: to the provider).
3. =fresh= competes by rank; same-rank fresh disagreements are conflicts now.
4. =open= competes by rank; same-rank open disagreements are =Stuck= until
   resolution decides value or conflict.
5. =secret= competes by rank; same-rank secret disagreements are conflicts now.
6. Every rank's =Stuck= and every deferred constraint is re-checked at each
   resolution that mentions one of its nulls.

Order independence of all six cases under every permutation and under
duplication: tested, passes. The two first-run failures (§2.3) were in the
Flat and Map normal forms, not in the ranking, and the fix (elements are
normal forms of their contribution lists) is now part of the definition.

** 4.2 Seam 2: provenance under retraction

The question: when =ν= resolves at a phase boundary, which circuit nodes are
invalidated, does =why= still answer correctly for facts derived before and
after, and what must the engine carry to avoid a full re-chase.

*** What can change, precisely

Let =F_ν= be the set of facts whose tuple carries =ν= (Rule 1), =S_ν= the set
of stuck instances blocked on =ν= (Rules 2 and 3), and =T_ν = { f : ν ∈
touches(f) }= the =(∪, ∪)= instance's preimage. Claim: after resolving =ν=,
every fact not in =T_ν= is unchanged, in tuple, in existence and in
provenance.

Argument. A fact outside =T_ν= has no alternative that passes through a
=ν=-carrying tuple, so substitution does not touch its =Times= nodes. Its
existence could change only through a negated literal or an aggregate whose
predicate gains or loses a tuple. By Rule 3 the negation was evaluated only
because no stuck instance existed for that predicate, so the resolution
cannot add a tuple through =S_ν=; and it cannot add one through
substitution (a re-spelled tuple is the same tuple to a negation that did
not mention =ν=, since a pattern that mentioned =ν= would be in =T_ν=). It
could *lose* a tuple only through a retraction, and retractions originate
only from a cell in =F_ν= becoming =⊤= (case 4 or a resolved =Stuck=), whose
cone is in =T_ν= by construction. So the definite fragment outside =T_ν= is
monotone across the boundary, and =T_ν= is the invalidation set.

/Addendum, 2026-09-28./ The argument assumes "no stuck instance existed for
that predicate" covers every way the predicate can gain a tuple, and a
stuck instance of the predicate itself does not: =q(x) :- p(x)= over a
stuck =p= has no stuck instance, yet gains =q(t)= through =S_ν= after the
boundary, so =not q(t)= and a count over =q= would flip (found by the
property test, =crates/dform-proptest=). The missing case: Rule 3 checks
negation patterns and aggregate group keys against the *may-derive* heads
(F DR-2 revised, last clause), transitively through positive reads, as
well as the stuck ones, per key; =attr= included, so a document whose
field comes from a reference to a resource that may be wanted is pending,
not definite. With that, "the negation was evaluated only because nothing
could still derive the pattern" holds, and the argument goes through.

Inside =T_ν=, three things happen, in order:

1. *Substitution.* Every =f ∈ F_ν= is re-spelled in place: same node id, same
   alternatives, each =Times= gains the world leaf =w_ν= for the resolution
   event. Facts that become identical merge (=⊕= of their alternatives; the
   prototype redirects the dead node). No node is invalidated.
2. *Re-collapse.* Every ranked cell that carried =ν= re-normalizes. A =Stuck=
   becomes =Val= (no change downstream except the re-spelling above) or
   =Conflict=; a deferred constraint becomes satisfied or =Conflict=. A
   =Conflict= *retracts* the =attr= row and derives =attr_conflict=.
3. *Unblocking.* Every instance in =S_ν= is re-evaluated; those that now fire
   insert facts with a =Times= that includes =w_ν=; those stuck on another
   null stay in =stuck/3=.

Only step 2 retracts, and only the =attr= rows of cells that went =⊤=. The
retraction propagates through the cone of that row: every =Times= that used
it dies, every fact left without alternatives is retracted in turn, and
through negation a fact *outside* the cone can now be derived (=not attr(T,
A, .p, V)= becomes true). That last effect is the one that requires
re-evaluating strata, not just walking the circuit: an absence leaf is not
a node in the DAG.

*** What =why= answers

Before resolution: a fact in =F_ν= shows its label in the tuple and its
derivation ends in the prelude's computed-attribute leaf over =want=. After
resolution: the same derivation plus the world leaf =w_ν= in every
alternative (tested: exactly one new leaf appears, and it appears in every
alternative, two hops downstream as well). A fact derived *after* resolution
by an unblocked instance shows =w_ν= as an ordinary leaf: "this exists
because apply #1 returned zones = [b, c]". A fact retracted by a =⊤= is
gone from the store and =dform why= on it reports "retracted at phase 1:
attr_conflict(...)" from the log, which is the one thing the audit log is
read for. =attr_conflict='s own =why= names the schema line, the contributing
rule and the world event (tested). Facts outside =T_ν= answer exactly as
before because their nodes were not touched.

*** What the engine must carry

- Per fact: its node id (already) and a small bitset or list of the nulls in
  its tuple (C's flag; cheap, since a tuple rarely carries more than a few).
- =stuck(RuleId, Bindings, Nulls)= as a relation, indexed by null label.
- Per null label: the set of cells (=(T, A, P)= groups) that received a
  contribution carrying it, so step 2 does not scan every cell.
- Per stratum: nothing new; semi-naive deltas for step 3's inserts are the
  ordinary =Fix= inputs.
- To do step 2's retraction *incrementally*: a counting or DRed scheme
  (Gupta, Mumick, Subrahmanian 1993) per stratum, which the absorptive
  circuit cannot provide (absorption discards counts) and the operator IR
  does not yet implement. The prototype's =retract= is DRed without the
  re-derivation pass and is only correct for non-recursive strata.

*** The honest v1

Steps 1 and 3 are deltas and run on the semi-naive engine unchanged. Step
2's retraction is rare (a null resolving to a value that violates a
refinement, or a same-rank pending conflict resolving to unequal) and its
consequences through negation are exactly what DRed exists for. v1 does not
implement DRed. When step 2 retracts anything, v1 *re-derives from scratch
every stratum at or above the retracted row's stratum*, carrying the lower
strata's facts and nodes forward and re-running the phase's substitution on
the way. Bound: let =E= be one full evaluation. A phase boundary costs at
most =E= (usually a small delta); the number of boundaries is the depth of
the null-dependency chain, =d=, typically 2 (create, then configure) and
rarely 3; so an apply costs at most =(d + 1) · E= of evaluation, and in the
common case where nothing goes =⊤= it costs =E= plus deltas. The DBSP
phase replaces this with retraction-by-weight (Deutch et al.'s
incremental circuits; Green, Ivan, Tannen 2010 for the provenance ring)
and that is one of the two reasons to build it.

Verdict: invalidation is exactly =touches(f) ∋ ν=; =why= is correct before
and after by construction (substitution keeps nodes, resolution adds a
leaf); v1 re-derives downstream strata only on the rare retraction, with the
bound above. C's expectation "phase resumption re-chases the strata
downstream of the resolved nulls" is confirmed as the fallback and shown to
be needed only when a cell goes =⊤=.

** 4.3 Seam 3: three touches on one aggregate

The three proposals each reach into the attribute aggregate.

- A: contributions to a sub-path are normalized into the schema-declared
  attribute (=.tags.team = "x"= is a contribution ={team: "x"}= at =.tags=) so
  one group per declared attribute exists.
- D: the dependency graph partitions =arg= and =attr= by resource type when the
  head's type is a constant, so the network module's read-vpc-write-subnet
  pattern is not a cycle; variable-typed writers (policy packs) declare
  =contributes= and land above all typed readers.
- B: schema refinements are joined into the cell so a violation is a =⊤=
  naming both the schema line and the contributor, checked even for values
  no rule reads.

Do they compose? §2.5 is the single definition; here is what had to give.

*Normalization and partitioning interact.* D partitions on the head's type.
If normalization happened after graph construction, =arg(T, A, .tags.team, V)=
and =arg(T, A, .tags, {...})= would be different heads; with path in the
partition they would be different nodes and a reader of =.tags= might be
placed below a writer of =.tags.team=. So normalization runs *first*, at
compile time, on every head with a constant path, and the partition uses the
normalized path. A head with a variable path is =(arg, T, *)=, which unifies
with every path partition of =T= and is therefore above nothing that reads
=T= and below everything; that is the correct, conservative placement and it
is the placement every such rule had under D anyway.

*Partitioning by type alone is not enough.* A's own baseline example
(=arg(iam.policy, A, .statements, S) :- ..., attr(iam.policy, A, .name,
"app")=) is a self-loop under type-only partitions and a compile error. That
rule is the natural way to say "add a statement to the policy named app". It
is not a bug, and telling the author to read =arg= contributions instead of
=attr= (D's mutating-webhook rule) is wrong here because =.name= *is*
assembled by the same aggregate. With =(type, path)= partitions the rule
reads =(attr, iam.policy, .name)= and writes =(arg, iam.policy, .statements)=,
no cycle. The =contributes= grant already names both a type pattern and a
path pattern, so the author has written the partition. *Override* of the
brief's "D's type-partitioning": partition by =(type, normalized path)=. D's
degenerate case (variable type and variable path: above everything) is
preserved, so nothing D accepted is rejected and A's example is accepted.

*Refinements have no rank and no partition of their own.* They enter the
cell as constraint contributions from EDB (=type_refine/3=), which is stratum
0 and therefore below every =(attr, T, P)= node; they attach to the group by
=(T, P)= and need =want(T, A)= to name the address, which is also below every
attribute reader. A refinement is never a reader, so it cannot create an
edge. Its witness is the schema fact's span, which is what the conflict
printer names. "Schema rank" would have been a fourth rank that nothing
could out-rank; making it a constraint component instead means the collapse
rule has one witness order (three ranks) and one constraint set, and B's
"a refinement at rank default still binds at rank force" is a theorem
rather than a special case.

*One more interaction the coordinator did not name.* The computed-attribute
prelude rule (§2.5, third contribution) writes =(arg, T, P)= for every
computed =P= of every type, from =want(T, A)= and schema facts. It is a
constant-type, constant-path head per schema row after expansion, so it
partitions cleanly and is below every reader of that computed path. If it
had been written with variable =T= and =P= (one generic rule over
=type_attr=), it would sit at =(arg, *, *)= and be above every reader, which
would put every =attr= reader in a cycle with it. The compiler therefore
*expands* the prelude rule per schema row before building the graph. That
is a one-line consequence of partitioning that a naive prelude would get
wrong, and it is the place a future implementer is most likely to trip.

Verdict: one aggregate definition, three touches composed, two things gave:
D's partition column set (type → type and normalized path) and B's "schema
rank" (a rank → a rank-blind constraint component). Normalization runs
first, the prelude expands per schema row.

** DR-2 Unknown values: classed nulls, stuck rules, phases

*Context.* Providers produce ids and endpoints at apply. The board's
proposal (opaque token, banned from bodies) is Terraform's =for_each=
restriction; C showed a two-phase GKE/kubernetes stack it cannot plan; D
showed the same with a clock.

*Decision.* =ref(T, A, Attr)= to a computed attribute is =Value::Null= with a
class from the schema (§2.2); to a configured attribute it is rewritten to an
=attr/4= join (A). Nulls may appear in any position; rules that need content
are stuck and recorded (§2.7, Rules 1-3); negation and aggregation over a
predicate with stuck instances are undetermined; resolution is substitution
after refresh, adopt, and each apply phase (Rule 4); the plan has definite,
pending, and undetermined sections; apply loops to undeformed under
=--max-ticks=. =fresh= nulls decide equality under UNA, so single-phase
programs (every example in this repo) stay single-phase. The chase, EGDs,
=some=, =choose= and quoted atoms from C are rejected; the only existential is
the prelude rule and §2.7 shows it needs no termination theory.

*Amendment (2026-09-28, proposal G decision 2).* The code keeps a =ref= to a
configured attribute as =Value::Ref=: resolved at apply from the program's
value (else the world's), an apply-order edge, printed =ref(...)=. It is not
rewritten to an =attr/4= join; G-6 relies on that. A ref to a computed
attribute is the labeled null as above.

*Consequences.*
- The "for_each depends on unknown" error class does not exist; the
  replacement is a plan line naming the pending group and its null.
- Provider configuration may depend on nulls (a phase-2 provider).
- The fake provider must stop synthesizing computed values from names and
  return them only from =Apply=, so the demos exercise phases.
- The =strict_unknowns= prelude policy (=deny(stuck_in_prod, ...) :- env(prod),
  stuck(_, _, _)=) restores Terraform's discipline for teams that want it;
  =dform init= offers it.
- Cost: =Value::Null=, =eq3=, the =Stuck= element, the =stuck/3= companion
  rule per content-position rule, the resolution step, and (v1) downstream
  re-derivation on retraction.

** DR-3 Open world vs encapsulation: interfaces, grants, private by default

*Context.* Every predicate global; typos are empty relations; two modules
defining =zone_index/2= silently union; policy packs write anywhere and that
is the feature.

*Decision.* A's module system unchanged: every predicate defined inside a
module is instance-private unless =export=ed; =input= / =output= are the
data boundary; writes to =arg/5= require =contributes arg to TypePat at
PathPat=, which is also the stratification partition (§2.6); =deny= / =warn=
need no grant; unknown predicates are compile errors everywhere; =extern=
declares provider-fed ones; user-defined global relations take
=contributes p.= (A's =iam_need= example). Provenance's =owner= instance
records every write.

*Consequences.* =component_def=, =use=, =component=, =component_scope/3=,
=param/2,3=, =import ... as= are replaced; =import "file"= remains a file
include. Cross-instance references go through =output/3=. The open world
survives in exactly two places: policy packs with a grant, and the global
read-only relations.

** DR-4 Case-based variable syntax: keep it

*Context.* Uppercase initial = variable blocks capitalized resource types
or keys. Alternatives: =$X=, =let=.

*Decision.* A's DR-4: uppercase-initial identifiers are variables, =_= is
the wildcard, =_Name= a named wildcard, lowercase-initial identifiers are
symbols; no sigil, no declaration form. Kubernetes kinds are attribute
values (strings); the type is =k8s.deployment=. D's "a path segment after a
dot may be any case" is rejected: =k8s.apps.Deployment= would make =X.field=
and =a.Field= look alike, and the provider maps the kind.

*Consequences.* As in A. The lexer has two token kinds and the grammar
states the rule in one line.

** DR-5 Symbol syntax: plain identifiers, qualified names, dotted keypath literals

*Context.* =sym= accepts =.=, =-=, =/=; no operator can be added; decide before
more =.df= files exist.

*Decision.* A's DR-5, verbatim: =ident := [a-z_][A-Za-z0-9_]*=; =QNAME= is
=ident.ident= with no whitespace; a keypath literal starts with a dot
(=.tags.team=, =."my-key".x=); =Var.field= is field access lowering to
=get/2=; =-= and =/= are always operators; hyphenated cloud names are
strings; addresses are =qname/ident= only in address positions. C's quoted
atoms ('us-east1-b') are rejected: a third literal kind whose only purpose
is to avoid quotes in zone names, at the cost of a symbol/string distinction
users will get wrong. D's bare =10.20.0.0/16= inet literal is rejected for
the same reason A gave: =inet("...")= takes a string and IPv6 needs it
anyway.

*Consequences.* Every =.df= file changes; =edition 2026= and =dform migrate=
are the prerequisite (DR-17).

** DR-6 Null, absent, and empty

*Context.* Datalog absence is "no fact"; APIs distinguish unset, null,
empty; this design adds labeled nulls and must not confuse the two.

*Decision.* Four things, four spellings:

| Concept      | Spelling                | Meaning                                                     |
|--------------+-------------------------+-------------------------------------------------------------|
| absent       | no =attr= row (=⊥=)     | provider receives no field; =required= absent is =deny(schema_required)= |
| API null     | =null= (=Value::JsonNull=) | a Flat value; legal only at =nullable(T)= paths; =null ⊔ v = ⊤= |
| empty        | =[]=, ={}=, =""=        | ordinary values; =[]= at a Set path and ={}= at a Map path are =⊥= and indistinguishable from absent, which is correct for those lattices |
| labeled null | =?type/addr#attr= (print only) | =Value::Null=; never written in source; never equal to =null= |

*Consequences.* Plan output prints the four differently and the diff treats
them as four things. =is_null/1= tests the API null; asking it of a labeled
null is a type error.

*Amendment (2026-09-28).* ={}= is "present and empty", a value distinct from
absent, where the schema declares the path =object= (a structure, not a
=map=) and none of its own fields is =required= (Kubernetes' =podSelector:
{}=, every pod): the document carries it and a diff compares it as a leaf.
At a Map or Set path, and wherever another contribution gives the object a
key, ={}= is still the identity.

** DR-7 Impure values: externs, results persisted in state

*Context.* Random suffixes, timestamps, generated passwords.

*Decision.* A's DR-7: no impure builtin; impurity enters through an extern
declared =persist=, keyed by its bound arguments, recorded in the plan file
and in =state.json='s persisted-externs section; =dform taint= forgets one
row; =time.now= is a non-persisted extern that =warn=s. The result of a

=random.password= has the same phase behaviour as a computed attribute (C's
observation) without being a resource (C's mechanism). The greedy
=allocate= aggregate (DR-15) pins through the same section.

*Consequences.* One state file section, one =why= leaf kind (extern call
with date), no new concept.

** DR-8 License: Apache-2.0, DCO, no CLA

*Context.* BSL produced OpenTofu overnight. A and D chose Apache-2.0; C

*Decision.* Apache-2.0 for compiler, engine, protocol, reference providers;

*Context.* B's ranked cells solve overrides commutatively; B had four

** DR-10 Provenance: absorptive circuit, always on

*Context.* A stored a derivation vector per fact; B stored owner maps and

*Decision.* C's circuit (§3.1), always on, with structural absorption,

** DR-11 The plan is a Z-set; conflict is a deny

*Context.* The prototype aborts on conflict and diffs by string; D defined
=desired − world=.

*Decision.* §2.8: =deformation= is the Z-set difference; =attr_conflict= and

*Consequences.* Nothing aborts inside evaluation; every error is a fact

** DR-12 Stratification partitions =arg= and =attr= by (type, normalized path)

*Context.* §4.3.

*Decision.* Two compiler-owned predicates get partition nodes on their
head's constant type and constant normalized path; =*= otherwise; the
=contributes= grant is the partition pattern; the computed-attribute
prelude rule is expanded per schema row before graph construction; every
other predicate is one node. B's general =partition= declaration rejected.

*Consequences.* A's baseline example compiles; D's degenerate case is

** DR-13 Refinements have exactly one home each

*Context.* L13 lowers refinements to =deny=; B checks them at join.

*Decision.* A refinement whose predicate is over the attribute's own value
alone and drawn from the checkable table (type tag, =>= <= < > != n=,
=prefix_len=, =enum=, regex) is a constraint contribution to the cell
(§2.5) and a violation is =⊤= naming the schema line; every other
refinement (cross-cell, counting, referencing other relations) lowers to a
=deny= rule. The compiler assigns each refinement to one home syntactically;
no violation is ever reported twice. On a null-carrying value the cell
check is deferred and the =deny= rule is stuck; both resolve at the same
boundary.

*Consequences.* Refinements are checked "even for values no rule reads"
(B's point) without a second reporting path.

*Context.* Rename is destroy and create; the research board asked for

*Decision.* §3.4.

*Consequences.* The rename ticket closes with =moved/3=; automatic

** DR-15 Solving: a greedy =allocate= aggregate with pins now, clingo behind a flag later

*Context.* CIDR assignment and zone placement are not deduction. D put
clingo in the engine; A and B put it behind an extern; D's own candid
section says a greedy allocator with pins covers most cases.

*Decision.* A prelude aggregate:

#+begin_src prolog
% One row per pool. Deterministic given (requests, pins): honour pins, then first-fit in key order.
alloc(Pool, allocate(Key, Bits)) :- pool_of(Key, Pool), request(Key, Bits).
assigned(Key, C) :- alloc(Pool, Asg), member(Asg, { key: Key, cidr: C }).
#+end_src

=allocate= is a stratified aggregate over its group; its result for =Key= is
=pinned(Pool, Key, C)= from state if present, else the lowest free block of
the requested size that overlaps no pinned or earlier-assigned block. The
executor writes =pinned/3= into =state.json='s persisted section after apply.
A request that cannot be satisfied yields =deny(alloc_exhausted, ...)=.
Removing a request never moves another. clingo ships later behind
=--features solve= as a =solve= block compiled to an extern of a bundled
provider, D's fragment, pins through the same section.

*Consequences.* D's CIDR example works today with no C++ toolchain; the
"count problem in Datalog clothing" is fixed by pins, not by ASP; users who
need anti-affinity plus capacity plus cost wait for the flag.

** DR-16 State is identity; the log is audit

*Context.* D made the log the unit of truth.

*Decision.* §2.8. =state.json=: identity mapping, persisted externs, pins.
The log: every tick's inputs, extern responses, apply results,
resolutions; read by =dform log=, =--as-of=, and =why= for retracted facts;
never by =plan= or =apply=.

*Consequences.* State surgery with =jq= still works in an incident; time
travel is a feature with a retention policy, not a dependency.

** DR-17 Editions, terminator, migration

*Context.* The grammar change breaks every file. D dropped the period after
=}=.

*Decision.* =edition 2026.= per file; a file without it is edition 2025 and
=dform migrate= rewrites it; the compiler supports the current and previous
edition. Block statements keep their period (=}.=): the parser's error
recovery at =.= is the reason the hand-written parser exists, and a block
that ends a statement without a terminator makes "one bad statement, one
diagnostic" ambiguous at every =}=. A lint offers to remove nothing.

*Consequences.* =dform migrate= handles: hyphenated symbols → strings;
path-position symbols → =.path= literals; =arg_add= → =arg= under a grant;
=setting_add= → =settings= block with =+==; =unique= → deleted; =arg_default=
→ =@default=; =component_def= / =use= → =module= / =instance= (with a
comment where cross-instance =component_scope= joins need hand rewriting).

** DR-18 Protocol v1: no =Subscribe=, no =Watch=

*Context.* D's symbolic providers subscribe to derived relations; D's
sources are informers.

*Decision.* v1 is the board's method table (Handshake, Configure, Schema,
Query, Read, Plan, Apply, Import) with two additions the synthesis needs:

*Consequences.* A provider author writes a Terraform-shaped plugin; nothing
about deltas.

** DR-19 Secrets: static labels plus secret nulls

*Context.* A: static labels plus a dynamic =Secret= value; C: secret nulls
plus a =label= semiring; D: static only.

*Decision.* A's static pass (E0301-E0305, one dataflow fixpoint over
predicate signatures) is the enforcement for rules. The dynamic half is
the =secret= null class: a provider-returned or extern-returned sensitive

*Consequences.* One value kind for "unknown to the engine" with three
classes instead of two mechanisms; the static pass's completeness claim
for rules is unchanged and remains the thing to attack (§10).

** DR-20 Deferred: DBSP and clingo

*Context.* A, C, D all want DBSP eventually; D wants it first.

*Decision.* The operator IR is DBSP-shaped and every addition in this

* 6. Grammar, final

A's grammar with the rank annotation and the removal of =arg_default=. The
reference for the hand-written =logos= + recursive-descent parser; the
example corpus in §7 is its test suite.

** Tokens

#+begin_example
IDENT    := [a-z_][A-Za-z0-9_]*                    ; symbol, predicate, function, keyword
VAR      := [A-Z][A-Za-z0-9_]* | "_" [A-Za-z0-9_]*  ; "_" alone is the wildcard
QNAME    := IDENT ("." IDENT)+                      ; no whitespace around "."
PATH     := "." PATHSEG ("." PATHSEG | "[" INT "]")*
PATHSEG  := IDENT | STRING
FIELD    := VAR "." IDENT                           ; one token; lowers to get/2
STRING   := "\"" ... "\""                           ; escapes \" \\ \n \t \u{...}
INT      := "-"? [0-9]+
ADDR     := QNAME "/" IDENT                         ; only in address positions
RANK     := "@default" | "@override"
keywords := edition provider stack import input output export contributes
            module instance policy apply resource settings scenario extern
            type decl when not in exists collect_set collect_list
            collect_ordered count sum min max lub_ranked allocate
            true false null secret persist where moved adopt lifecycle
            ignore_changes
#+end_example

Keywords are token kinds. =true=, =false=, =null= are literals. A keyword may
be a keypath segment (=.type=) because =PATH= is one token. There is no
=?label= token: nulls are never written.

** Statements

#+begin_example
program    := (stmt ".")*
stmt       := edition | provider | stack | import
            | input | extern | typedecl | decl
            | module | instance | policy | apply
            | resource | settings | scenario | when
            | lifecycle | moved | adopt | ignore
            | rule | fact

edition    := "edition" INT
provider   := "provider" IDENT "{" kv* "}"
stack      := "stack" QNAME "{" kv* "}"
import     := "import" STRING
input      := "input" IDENT ":" type ("=" term)? ("where" body)?
extern     := "extern" QNAME "(" bindarg ("," bindarg)* ")" "persist"?
bindarg    := ("+" | "-") IDENT (":" type)?
typedecl   := "type" QNAME "{" attrdecl* "}"           ; user schema for open types
attrdecl   := PATHSEG ":" type flag* ("where" body)?
flag       := "required" | "computed" | "id" | "sensitive" | "nullable"
decl       := "decl" IDENT "/" INT | "decl" IDENT "(" (VAR ":" type) ("," VAR ":" type)* ")"
            | "decl" "type" QNAME "open" | "decl" IDENT "/" INT "mixed"

module     := "module" IDENT "{" (stmt ".")* "}"
instance   := "instance" IDENT IDENT "{" assign* "}" (":-" body)?
policy     := "policy" IDENT "{" (stmt ".")* "}"
apply      := "apply" IDENT
grant      := "contributes" "arg" "to" typepat "at" pathpat | "contributes" IDENT
typepat    := QNAME | "_"
pathpat    := PATH | "_"

resource   := "resource" QNAME (IDENT | VAR) RANK? "{" assign* "}" (":-" body)?
settings   := "settings" (IDENT | VAR) RANK? "{" assign* "}" (":-" body)?
assign     := blockpath ("=" | "+=") term RANK? ","?
blockpath  := PATHSEG ("." PATHSEG | "[" INT "]")*        ; PATH without the leading dot
scenario   := "scenario" IDENT "{" (stmt ".")* "}"
when       := "when" lit "{" (stmt ".")* "}"
lifecycle  := "lifecycle" "(" QNAME "," addr "," IDENT ")" (":-" body)?
moved      := "moved" "(" QNAME "," addr "," addr ")"
adopt      := "adopt" "(" QNAME "," addr "," term ")" (":-" body)?
ignore     := "ignore_changes" "(" QNAME "," addr "," PATH ")" (":-" body)?

rule       := head ":-" body
fact       := atom
head       := atom (RANK)?                                 ; at most one aggregate term; RANK only on arg heads
body       := lit ("," lit)*
lit        := "not" atom | "not" "exists" "(" body ")" | atom
            | term cmpop term | term "in" term | term "not" "in" term
atom       := (IDENT | QNAME) "(" (term ("," term)*)? ")"
            | IDENT "{" (IDENT ":" term ("," IDENT ":" term)*)? "}"
#+end_example

=+== is legal only on a path whose lattice is =Set=, =Map= or =Keyed= (it is
documentation; ==== means the same thing there). =+== on a Flat path is a
compile error that names the lattice. =RANK= on a =resource= or =settings=
header distributes to every assignment in the block; on an assignment it
applies to that leaf; on an =arg= head it applies to the contribution. A
=RANK= on a =Set= path is a compile error.

** Terms

#+begin_example
term       := add
add        := mul (("+" | "-") mul)*
mul        := unary (("*" | "/" | "%") unary)*
unary      := "-" unary | primary
primary    := INT | STRING | "true" | "false" | "null"
            | VAR | FIELD | IDENT | QNAME | PATH | ADDR
            | call | list | object | comprehension | aggregate | "(" term ")"
call       := (IDENT | QNAME) "(" (term ("," term)*)? ")"      ; ref(T, Addr, PATH) is a call
list       := "[" (term ("," term)*)? "]"
object     := "{" (objkey ":" term ("," objkey ":" term)*)? "}"
objkey     := IDENT | STRING
comprehension := "[" term "|" body "]"                     ; lowers to collect_set
              |  "[" term "ordered" "by" term "|" body "]"  ; lowers to collect_ordered
aggregate  := ("collect_set" | "collect_list" | "count" | "sum" | "min" | "max") "(" term ")"
            | "collect_ordered" "(" term "," term ")"
            | "allocate" "(" term "," term ")"
type       := IDENT | QNAME | IDENT "(" type ("," type)* ")" | "enum" "(" IDENT ("," IDENT)* ")"
            | "secret" "(" type ")" | "nullable" "(" type ")" | "ref" "(" QNAME ")"

term position a function, different namespaces (E0101); =ADDR= only in
address positions (second argument of =want=, =arg=, =attr=, =adopt=,
=lifecycle=, =ignore_changes=, =moved=, and of =ref=); elsewhere =a.b / c= is
division; block assignments may omit commas.

* 10. Candid section

** What the synthesis cannot do

*Explain itself in one sitting.* A reader must hold: three ranks, three
null classes, =Stuck= as distinct from =⊤=, stuck rules as distinct from
stuck cells, phases as re-evaluation boundaries, and a =deny= with three
outcomes. Each is small; together they are more than "known after apply".
The plan printer carries the load, and if the sections in §7.4 do not read
naturally to a Terraform user the design has failed socially whatever its
semantics.

*Cheap retraction.* A phase boundary that turns a cell =⊤= re-derives the
downstream strata (§4.2). Bounded, rare, and still a full evaluation on a
bad day. DBSP fixes it and DBSP is deferred.

*Whole-set override.* No =seal=, no rank on sets. "In prod the tag set is
exactly these" is not expressible; =ignore_changes= or a Flat schema for the
path are the tools. A's DR-1 reasoning stands and it will be the first
feature request.

*Arithmetic over unknowns.* An open null under =inet_subnet= is stuck. C's
c-tables with arithmetic conditions, B's abstract-interpretation
signatures on builtins, D's clock: all three had a story; this design has
"wait for the boundary". It is honest and it is the least helpful of the
four.

*Counting provenance and bag semantics.* Absorptive storage throws away
"how many ways". No infrastructure question needs it today. A closed door.

*Two authors appending to one ordered list.* Still not a lattice (A's
candid point 5). =Keyed= covers the cases with a key; the rest is one
author per list.

** Which tickets it makes harder

| Ticket                              | Why harder                                                                                     |
|-------------------------------------+------------------------------------------------------------------------------------------------|
| Plan output                         | must render four sections, ranks with owners per leaf, nulls with labels, deferred checks, redacted secrets |
| Apply executor                      | owns boundaries, downstream holds, re-evaluation and policy re-check between phases; more than a DAG walk |
| Tests                               | golden tests must snapshot circuits and phase sequences, not one fact set; circuit hash-consing must be deterministic across platforms |
| Plugin protocol                     | =Schema= carries classes and refinements; =Apply= returns computed values for resolution; a plain "facts out" schema is not enough |
| Fake provider as conformance harness | must return computed values only from =Apply= and mark secret ones, or no demo exercises a phase |
| Declarative providers               | every static check reads the schema; an OpenAPI-derived schema with gaps makes a partial schema worse than none (A's point, unchanged) |
| Language editions                   | =dform migrate= cannot mechanically rewrite cross-instance =component_scope= joins into =output= wiring, nor decide which of two =arg= writers should become =@default= |
| Reactive inputs / controller mode   | provenance retraction under DBSP with the =Stuck= element and resolution-as-substitution is a design that no one has built; C's incremental-chase worry applies to the boundary step even without EGDs |
| Multi-stack orchestration           | less pressing than under A (phases replace the two-stack rule for the common case) but cross-stack nulls are not designed: a =stack_output= that is an open null in the upstream stack is a constant or absent downstream, never pending |

** Where it is most likely wrong

1. *Rule 3 is too coarse.* "Any stuck instance for a rule with head =p=
   makes every negation over =p= undetermined" is what makes the definite
   fragment monotone across boundaries and it is one line to implement. It
   will also make a =deny= undetermined because an unrelated rule for the
   same predicate is stuck on an unrelated resource. If that happens in
   practice the refinement is per-key (stuck instances record their head's
   bound key columns; a negation is undetermined only if its pattern
   unifies with a stuck head), which costs a unification per negation and
   loses nothing else. I would ship coarse and measure.

2. *=Stuck= at any rank propagates.* Chosen for symmetry with =⊤= at any
   rank. The losing-rank =Stuck= case (two defaults that might disagree,
   overridden by a normal value) is a real program that will wait on a
   null it does not need. If it recurs, the rule becomes "=Stuck= at a
   losing rank is a warning, not a stuck", and the =⊤= rule should probably
   follow it, which reopens B's argument.

3. *The (∩, ∪) phase instance and provenance truncation.* With =k = 8=
   alternatives and a =truncated= flag, a fact whose only null-free
   alternative was truncated is reported pending when it is definite.
   Conservative, and it will surprise someone with a heavily redundant
   rule set.

4. *Secrets have three mechanisms after all.* Static labels for rules, the
   =secret= class for values, and the =label= instance for redaction. DR-19
   calls the second and third one mechanism; a reviewer could reasonably
   call them two. The interaction that matters (a static =public= position
   receiving a runtime =secret= null from a mislabelled provider schema)
   ends in a conflict at the same-rank rule or a stuck read, never in a
   printed byte, which is the property that matters; the argument that it
   never prints is the part to attack.

5. *Variable instance segments* (=output(network.IA, vpc, A)=) are kept
   from A with A's own warning. The next request will be =instance network
   Name {...} :- region(Name)=, and then instances are data and interfaces
   are checked at evaluation time. The honest alternative is to forbid it
   now and make the root enumerate instances by hand; this design does not,
   and that is a bet on the smallness of the feature.

6. *The greedy allocator.* First-fit with pins is deterministic and
   removal-stable, and it is also a policy ("lowest free block") that
   someone will want to change (largest-gap, per-zone pools). Every knob
   added to =allocate= is a step toward the solver stratum that DR-15
   deferred; if three knobs appear, ship clingo instead of a fourth.

7. *Prototype scope.* The lattice and circuit are pure functions with 16
   tests; nothing in §2.6 (partitions), §2.7 (stuck rules and boundaries) or
   §2.8 (the Z-set plan) has run. The claims there are reasoned from the
   proposals and =engine.rs=, and the first thing to build after the parser
   is the partition graph over the six example files, because DR-12 is the
   decision most likely to reject a program the examples consider fine.
