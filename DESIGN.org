** TODO [#B] Extend ranks to Set and Keyed (reopens E DR-9)
E restricted ranks to Flat for simplicity, not for a semantic reason. A ranked
Set cell is three Sets joined pointwise; collapse takes the highest non-empty
shelf, so =@override= means "replace the whole set at this rank". Order
independence survives since it is the same product construction. Rank is a
declared compile-time priority, so no runtime clock is needed and two runs on
the same commit collapse identically, which LWW could not promise. Decide:
a =@default= set is discarded, not unioned, when a higher shelf is non-empty.
Closes the "no whole-set override" tradeoff. Element-level override for Keyed
already exists via ranked Flat leaves.

** TODO [#A] Apply re-diffs against a saved plan

** R-1 The clause comes after the head, and the word is =where=
*Context.* H-3 made =if= the one clause word and put it first inside a
block. =if= reads as a boolean guard, so a generator (=if zone(z, n)=) reads
wrong; =for= reads as a loop, so a rule (=p(x) for q(x)=) reads wrong; and
the clause-first block is the one statement whose shape hides that the
block is the head of a rule, while its header names variables the reader
has not seen yet. =:-= is honest but is the token a Terraform reader
closes the file on, and =where= loses nothing against it.
*Decision.* Every statement is =head where body=; a block is a head:
=resource T n { .. } where B=, =settings n { .. } where B=, =instance m i {
.. } where B=, =p(x) where q(x)=, =deny "m" where B=, =let k = t where B=,
=set R.p = t where B=, =output k: T = t where B=. A multi-line body is
=} where { lit NL lit }=. =if= is gone. Refinements change word so that
=where= has one meaning: =input replicas: int check 1 <= replicas <= 10=,
=db.backup_days: int check ..=, and =type_refine= keeps its name.
*Not taken.* =for= (a second word for blocks), =:-= (audience), keeping
=if= with the trailing position (the position is the larger problem, but
the word was free to fix in the same landing).
*Consequences.* One landing rewrites lexer, parser, resolver, fmt,
tree-sitter, the Emacs mode, the LSP, every =.df=, docs/grammar.md and the
README; every golden plan is byte-identical. The tour's section 3 text
("the block below has a where clause") is the one place the word is
taught.

** R-2 A variable bound once is an error
*Context.* =reaches(a, c) if reaches(a, b), link(bb, c)= planned four VPCs
instead of two with no diagnostic (verified). A typo in a variable is a
cross product, and the output is cloud resources.
*Decision.* A variable with exactly one occurrence in its rule (header,
clause, entries and interpolations counted together) is an error naming
it; =_x= opts out. An error, not a lint (H-1).

** R-3 =let= is a cell of the attribute aggregate
*Context.* H-6 made =let= a one-column relation; two rows silently
produce two of everything that reads it (verified: two =let n= rows, two
resources). Inputs and settings are already cells.
*Decision.* =let k = t [@rank] [where B]= contributes to the cell
=(let, "", k)= (scoped like an input in a module). Rows that agree merge;
rows that disagree at the winning rank are a conflict naming both; a
=@default= row is legal. A read of =k= reads the collapsed cell, so a
=let= holding a reference still reads through it (H-6 stands). The tour
teaches "inputs, settings and lets are cells; resources and facts are
rows".

** R-4 No explicit reference spelling
*Context.* G-6 decides reference versus read by position. A =ref= prefix
(=vpc_id = ref vpc.id=) was proposed as the one override.
*Decision.* Not taken. The positional rule is total and is exactly Rule 2's
content positions; there is no parse-level ambiguity. The surprise is
one-directional (a content read of a computed path, usually an
interpolation, makes the block wait a tick) and a prefix cannot help an
interpolation, which needs the bytes. Instead: a compile-time note at a
content read of a schema-computed path inside a block ("reads
=db.endpoint= now: this block waits for tick 2; =host = db.endpoint= is an
edge and applies at tick 1"), from the schema's computed flags.

** R-5 =contributes= and relation =export= are deleted
*Context.* A pack grants itself reach into every resource's cells; nobody
on the receiving side opts in. The grant duplicates the pack's own =set=
statements, =why= already names every contribution's owner, and the
partition pattern it gave the stratifier (F DR-12) is the head's own
constant type and path.
*Decision.* =contributes= goes. =export p= goes: a module reaches a global
relation only through an output the stack wires (=network_of(t, v) where
spoke(t), v = network[t].vpc=, as the tour does). =export type= stays.
=use= stays as a pack's activation (what =instance= is for a module).
Ranks are the ownership model. Module-private relations stay private.

** R-6 One function registry, in dform syntax; qualified names
*Context.* The engine keeps two hand-written lists of function names, the
LSP a third signature table, the secrets pass a fourth list of inspecting
functions. =cidrsubnet= sits beside =inet_subnet=, =concat= beside
interpolation, =gref= beside =ref=, =collect= beside =collect_set=; none of
the four has a corpus use.
*Decision.* Functions are declared in signature files shipped with dform,
=std/inet.df=, =std/str.df=, =std/list.df=:
#+begin_example
package inet
fn subnet(net: inet, bits: int, n: int) -> inet
fn host(net: inet, n: int) -> ip
fn overlaps(a: inet, b: inet) -> bool
#+end_example
A signature carries what the compiler needs beyond the body: partial
(=-> T?=: no value, the rule does not fire), =inspects= (default) or
=forwards= (the secrets pass, E0301), =forwards nulls= (Rule 2 treats a
function argument as a content position unless the function says so;
today only =collect=). Purity is not a flag: every function is pure and
deterministic, impurity enters only through externs (E DR-7). The Rust
bodies are looked up by qualified name. Engine, LSP, =dform doc=, the type
checker and the secrets pass read the same files; the lists go. Names: the
namespace is the type the function is about (=inet.subnet=, =str.split=,
=list.join=); conversions are constructors named by their type (=int(s)=,
=string(x)=, =inet(s)=, =ip(s)=), so =to_int= and =to_string= go. The
prelude, bare, is the constructors, =format= and =len=; everything else is
qualified. Deleted: =cidrsubnet=, =gref=, =concat=, the =collect= alias,
E's =collapse= (the engine uses =collapse_shadow_aware=).
A single first-segment registry decides what a dotted name's head is: a
type namespace (=net=), a provider's externs (=file=), a function package
(=inet=), a module with instances (=network=), =settings=, =world=,
=stacks=. A collision is an error naming both.

** R-7 Function packages: the declaration is the ABI
*Context.* Someone should be able to ship functions as a =.wasm= (or, for
trusted code, a =.so=) and have them importable. Out of scope to build;
in scope to not preclude.
*Decision.* A function package is a directory: one signature file (R-6)
and a body a host loads. Hosts: the Rust table in the binary (today), a
wasm component (R-13), a shared object (gated on =trusted = true= in its
=dform.toml= entry). The host trait is name, arity, the R-6 properties, and
=call(args) -> Option<Value>=. Across a boundary the calling convention is
the protocol's =Value= (=dform-wire=), prost-encoded in and out: one
encoding for providers and functions, and a trivial C ABI. A package is
sourced and pinned like a provider: =[functions] geo = { source, version
}= and the lockfile hash. A provider package may ship a function package
under its namespace. Externs and functions never share a mechanism: an
extern is a relation with binding modes, demand-driven, possibly
persisted, answered by a provider; a function is pure, in a term, cheap,
in-process.

** R-8 Externs come from providers; =extern= leaves programs
*Context.* =extern file.json(+path, -value)= in a program copies what the
provider's =SchemaResponse.externs= already carries.
*Decision.* =provider file {}= brings =file.json= and =file.text= into
scope with their modes; a program never declares a provider's extern.
=file=, =env= and =random= are built-in fact providers, started
in-process, declared like any provider (a built-in needs no
=dform.toml= source). =env_var(NAME)= becomes =env.var(NAME)= under the
same rule. =extern= survives only in text that is not a program file
(provider schemas, the compiler's tests), where H-15 already keeps the
core.

** R-9 Head aggregates are cut
As H section 10.2, already a WIP ticket: =len([x | B])= and list functions
replace =count=, =sum=, =min=, =max= in heads; =collect= stays internal
behind the comprehension. This removes a category of callable from R-6.

** R-10 Long bodies: fmt breaks by literal count; bindings first
*Decision.* =fmt= puts a body one literal per line when it has more than
three literals, whatever the width. =fmt= checks (does not rewrite) that a
body's binding literals precede the literals that read them, and a body
over five literals gets a lint suggesting a named relation (the tour's
=network_of=).

** R-11 Effects are legible: interface first, one shape for every remote read
*Context.* A module reads cells, writes cells and offers outputs; the
statements that say so are scattered through its body, and a remote
stack's output is spelled =stack_output("platform.cluster[env=prod]",
"endpoint", e)=, a raw core relation, while a module's is
=network[t].vpc=.
*Decision.* (a) In a module, policy or scenario the interface comes first
and =fmt= enforces the order: =input=, =output=, =export type=, then the
body. (b) A remote output is =stacks.platform.cluster[env="prod"].endpoint=
(a remote named in =dform.toml=, its stack, its key), lowering to
=stack_output= exactly as =m[e].k= lowers to =output=; H-15 then rejects a
program that writes =stack_output=. (c) =dform dev effects TARGET= prints,
per module instance, policy and stack: the cells it reads (inputs,
settings leaves, world types, externs), the cells it writes, and the
outputs it offers, from the partition graph. The needs/offers design
(parking lot) is the static form of this view and waits for it.

** R-12 Apply asks again when a tick adds an address; a signed plan bounds its groups
*Context.* =apply= confirms once, at tick 1 (=src/cli.rs=, the
=confirm= call), where a pending group reads =iam.policy[?] x unknown=; tick
2 then creates any number of them without asking. =apply PLAN.json= admits
any new address at a later tick wherever the file has a pending group of
that type (=zset::file= staleness, the =grouped= clause), so an approver's
signature does not bound what is created.
*Decision.* A batch apply asks at any tick whose plan holds an address the
tick-1 plan did not list, printing only the new ones; =--yes= skips, the
controller never asks. The plan file records each pending group's head
pattern and the bindings its stuck instance holds; an instance that
appears at a later tick must unify with a recorded group or the apply is
stale. Until that lands, an apply with =--approval= whose file holds a
pending group is refused, naming the group.

** R-13 The provider contract is WIT; the host is wasmtime; gRPC is a bridge
*Context.* The =Provider= trait (=plugin/backend.rs=) is transport-free
already: =submit= and =next_completed= over =Call=/=Reply=, with process
(gRPC), direct and wire backends. The component model with wasip3 gives
streams and futures, which removes the two host-side objections
(concurrent Apply calls, =Query= as a stream). The toolchain here ships
=wasm32-wasip2= only (rustc 1.99, 2026-09-28); wasmtime 49 is available.
*Decision.* The canonical IDL is a WIT package, =wit/dform-provider.wit=,
written for 0.2 now with the 0.3 async shape recorded beside each call
(=query= returns =list<row>= now, =stream<row>= then; =apply= blocks now,
returns a =future= then). The proto mirrors it until the bridge exists,
then goes. A provider is a component instantiated once per run (SDK
state, credentials, connection reuse), with wasmtime epoch deadlines per
call for timeouts; a trap mid-call is =MaybeApplied= exactly as a dead
process is, so idempotency keys and the =managed= capability stay.
=--parallel= on 0.2 is an instance pool of N identically configured
instances; on 0.3 one instance. A function package (R-7) is a component
with no resources, on the same host. The mock is built as a component
first (no SDK, the conformance reference) and =provider check= must pass
on both hosts: that is the proof the contract is host-free. The direct
and wire backends become "the mock instantiated in-process".
*The bridge.* Go and Python SDKs do not run on WASI; they are reached by
one component, =dform-bridge-grpc=, that speaks the WIT inward and gRPC
outward over wasi-sockets to a sidecar the host spawns (WASI has no
process spawn; the host keeps that one privileged hook, Terraform's
plugin-launch shape). It needs wasip3 and an HTTP/2 client over
wasi-sockets, neither available today. Until it passes =provider check=,
=dform-grpc= is the native bridge, frozen: nothing is added to it.
*Spike.* =dform-k8s= on =wasm32-wasip2= with wasi-http, reporting whether a
Rust SDK provider builds and passes =provider check= unchanged. Its answer
decides whether wasm is the default provider host or the exception.

** R-24 A registry is a bucket: providers and function packages live where state does
*Context.* Terraform's registry is a service because a provider is a
native binary per OS and architecture. Under R-13 a provider is one
component file, platform-independent, content-addressed. dform already
has a store with conditional writes (=store.rs=: =local= and =s3=, ETags,
=If-None-Match= for new objects), credentials for it, =[remotes]= in
=dform.toml= naming other backends, and DSSE/JWKS verification
(=approval.rs=). What is missing: a remote provider source, a lockfile
and cache (DESIGN.org "Provider declaration, lockfile, and local cache",
still open), signing, and the schema beside the artifact.
*Decision.* A registry is a prefix in any backend state can live in,
named in =dform.toml= with the same term as a backend:
#+begin_example
[registries]
acme = { backend = 's3("acme-dform", "providers", {endpoint: "..", region: ".."})', keys = 'jwks_file("acme.jwks.json")' }
dev  = { backend = 'local("../registry")' }

[providers]
aws = { source = "acme/aws", version = "2.1" }      # registry/name
gcp = { source = "providers/gcp" }                   # a path, as today

[functions]
geo = { source = "acme/geo", version = "0.3" }
#+end_example
Layout under the prefix, immutable per version:
=NAME/VERSION/provider.wasm= (or =package.wasm= for functions),
=NAME/VERSION/manifest.json= (name, version, kind, protocol version,
sha256 of the artifact, the schema's sha256, the signing key id),
=NAME/VERSION/schema.df= (the provider's =Schema= answer as facts, so
the resolver and the LSP know its types and externs without
instantiating it, and offline), =NAME/VERSION/manifest.dsse= (the
manifest signed, Ed25519 DSSE as approvals are), and =NAME/index.json=
(the versions, written with =If-Match=). A version is written with
=If-None-Match: *= and never overwritten; yanking is an index flag.
Resolution: the version constraint (Cargo semver, as today) against the
index, the artifact fetched into =dform.state/cache/providers/<sha256>=
and verified against the manifest's digest and, when the registry has
=keys=, the envelope against them; =dform.lock= records name, version,
sha256 and key id, and a run with a lockfile never consults the index.
A registry without =keys= accepts unsigned manifests (local
development); one with them refuses an unsigned or unverifiable
artifact naming the key. Publishing is a client operation, no service:
=dform provider publish PATH --to acme [--key FILE]= runs =provider
check= first, writes the four objects, updates the index. Mirroring is
a copy. Air-gapped is =local=. Built-in providers (the mock) are
publishable like any other, which is how the registry is tested.
*Why it is easy.* IAM on the bucket is the access control, the same
credentials reach state and providers, nothing runs, and the
conditional-write store is the implementation. A public registry later
is a public bucket and a well-known key, not a product.
*Not taken.* OCI artifacts (a second store with its own auth; revisit
if a user asks for GHCR), a registry protocol over HTTP (a service),
per-platform native providers in the registry (the bridge's sidecars
are deployed like any other binary, not through dform).

* Vocabulary
The name is Terraform minus terra plus Datalog, and it reads as "deform" aloud.
Use the pun consistently in CLI output, docs, and diagnostics.

| Term        | Meaning                                                          |
|-------------+------------------------------------------------------------------|
| deformation | a plan: the set of actions that reshape a stack toward intent     |
| undeformed  | a stack whose plan is empty; the world already matches intent     |
| deform      | apply a deformation (=dform apply=; =dform deform= as an alias)   |
| =.df=       | a dform source file; Datalog facts, or the differential           |
| intent      | the derived =want= / =attr= relations; what the program asks for  |
| world       | refreshed provider state; what exists                             |
| drift       | a deformation caused by the world moving, not the program         |

Example CLI lines:
- =plan: 3 deformations (2 create, 1 update)=
- =stack renfry.prod is undeformed=
- =drift: 2 deformations from world changes since last apply=

** DONE [#A] Attribute assembly: lattice merge vs fixpoint side effects
DECIDED (E DR-1, F DR-1): one ranked lattice aggregate over arg contributions; Flat/Map/Set/Keyed, no Bag; three ranks on Flat only; conflict is top naming every witness and derives a deny. All four ad hoc mechanisms deleted.
Infra needs functional dependencies (one value per attribute). Pure Datalog has
none, so the prototype bolts on four separate non-monotonic mechanisms:
- functional-predicate rewrite for =arg= and =output= (=engine.rs:96-101=, =apply_functional_pred=)
- =unique= declarations (=enforce_uniques=, checked only at the end)
- =merge_rule= + =arg_add= (=merge.rs=, applied in =ir.rs= after eval)
- =setting_add= mutation inside the fixpoint loop (=engine.rs:113=, =apply_setting_add=)
Each has its own conflict semantics and timing. CUE solves the same problem
with one value lattice.
*** Options
1. Keep Datalog pure for relations. Attribute assembly becomes a separate
   compile step after the fixpoint: collect all =arg=/=arg_add= facts, merge by
   one lattice law, conflicts are errors with provenance.
2. Make attributes a lattice type inside the engine (Flix / Bloom style
   monotone aggregation).
3. Attributes as a lattice aggregate: a derived =attr(Type, Name, Path, Value)=
   relation computed from =arg= / =arg_add= contributions by one merge law.
   Consumers are pushed to a higher stratum by the stratified-aggregation rule.
*** Recommendation
Option 3. Option 1 as first written fails because rules read attributes in
bodies today (=modules/network.df= joins on the VPC cidr through =arg=;
=policies/baseline.df= negates over it). Post-fixpoint assembly would show those
rules raw contributions, not merged values. Option 3 unifies this ticket with
the aggregate-stratification ticket into one mechanism, removes all four ad hoc
paths, and keeps the engine a textbook stratified Datalog with a lattice
aggregate, which is CUE's footing plus closures and policy.
*** CRDT framing
A join-semilattice merge is commutative, associative, idempotent: contributions
from resources, modules, and policy packs commute regardless of load order or
stratum timing, and re-evaluation is idempotent. Conflict is the lattice top,
as in CUE. Precedent: Bloom^L (Datalog over lattices), Flix, LVars, CALM.
Production precedent: Kubernetes server-side apply, field-wise merge with
recorded field managers and conflicts naming both writers.
*** Acceptance
- =apply_functional_pred= and =apply_setting_add= deleted from the fixpoint loop
- merge is order-independent: shuffling statement order yields identical =attr/4=
- one merge law documented in =docs/=; =merge_rule= becomes an annotation on it
- conflict error names both contributing rules with file:line

** DONE [#A] Unknown values: what may a rule observe at plan time?
DECIDED (E DR-2, F DR-2): ref is a classed null (fresh/open/secret) from the schema; content-needing literals are stuck per key; phases derived from null dependence; round-0 resolution against the world before diffing; strict refusal available as a policy pack.
Real providers produce ids, arns, endpoints only at apply. The fake backend
hides this by synthesizing computed values from strings (=fakecloud.rs:498=
=computed_ref=), so every value is known at plan time. Datalog has no
"known after apply": an unknown cannot unify, be negated, or be aggregated.
*** Proposed rule
Cloud outputs enter the program only as discovery facts from a previous apply
(=cloud_attr= / =cloud_computed= / =stack_output=). =ref(T, N, Attr)= is an opaque
token: legal in attribute values, illegal in rule bodies, comparisons, and
negation. Compiler rejects violations using the provider schema (see schema ticket).
*** Consequence
Multi-phase apply (create VPC, learn id, then create subnets) is handled by the
provider through the dependency order, never by re-running the fixpoint.
Document this explicitly; it is the same restriction Terraform has on
=count= / =for_each=.

** DONE [#B] Open world vs encapsulation
DECIDED (E DR-3): modules with input/output/export/contributes, private by default; undefined predicate is a compile error; policy packs are modules with a grant; stratification partitions every type-keyed core predicate by constant type (F DR-12).
Every predicate is global. A policy pack can =arg_add= to any resource and that
is the feature (=policies/baseline.df:8=). Costs:
- two modules defining =zone_index/2= silently union
- a misspelled predicate is an empty relation, no error (verified: =envv(prod)= yields 0 resources)
- nothing says where an attribute came from
Aspect-oriented config survives at team scale only with provenance tooling and
some visibility control. See module interfaces and provenance tickets.

** TODO [#A] Aggregates are not stratified
=compute_strata= treats a rule whose head contains =collect*= as an ordinary
positive edge. A consumer in the same stratum observes a partial aggregate
mid-fixpoint and the stale derivation is never retracted.
*** Repro
#+begin_src prolog
n(1).
n(2) :- n(1).
n(3) :- n(2).
all(collect_set(X)) :- n(X).
snap(L) :- all(L).
#+end_src
=dform query snap= prints three facts; correct output is one.
The =output(private_subnet_ids, [...])= pattern in =modules/network.df= has this
shape and only works because =arg= gets overwritten by the functional rewrite.
*** Fix
Aggregate head predicates get a negative edge to every body predicate, so
consumers land in a strictly higher stratum. Recursion through an aggregate
becomes a compile error. Precedent: standard stratified aggregation (Soufflé,
LogicBlox, Mumick & Pirahesh).

** TODO [#A] Unknown predicates are silently empty
No check that a body predicate is defined by some fact, rule, builtin, or
provider. Typos produce empty relations and zero resources with no diagnostic.
*** Fix
After lowering, error on any body predicate with no definition. Allow an
explicit =extern pred/N.= for discovery facts a provider may or may not supply.

** TODO [#A] Negation over mutated facts is unsound
=setting= is mutated by =apply_setting_add= inside the loop, but stratification
only sees rule-defined predicates. =not setting(prod, audit.enabled, true)=
(=policies/baseline.df:24=) can be evaluated before the merged value exists.
Goes away with the lattice decision; until then, run =setting_add= merging
before stratum 0.

** TODO [#B] Functional predicate overwrite hides ordering bugs
=apply_functional_pred= silently replaces an existing =arg= value when a second
rule fires in a later iteration. Conflicts are only caught when both rules fire

** TODO [#B] Ordered lists cannot be derived

Listener rules, firewall priorities, container args are ordered. Symptom: the

See ordered aggregation language ticket.

** TODO [#B] Silent string-to-int coercion
=as_i64= (=engine.rs:1317=) parses strings as integers, so ="10" + 1= works and
="abc" + 1= silently fails the rule. Make coercion explicit (=to_int=).

** TODO [#C] Fixpoint iteration cap is arbitrary
=iterations > 200= bail (=engine.rs:70=). With semi-naive evaluation this cap is

* Parser and grammar
=src/dform.pest= is already a PEG (pest). The problems are the grammar itself
and the untyped tree walker, not the choice of PEG.

** TODO [#A] Symbol syntax swallows future operators
=sym= and =pred= accept =.=, =-=, =/= inside bare tokens (=dform.pest:sym=), so
=a-b= is a symbol not subtraction and =x.y= is a symbol not field access.
Neither operator can ever be added without breaking every program.
*** Fix
Plain identifiers only. Dotted paths become an explicit path form (quoted, or a
=path= rule that is only legal in keypath positions). Hyphenated cloud names
become strings. Decide before any more =.df= files are written.

** TODO [#A] Spans are discarded
pest provides a span on every =Pair=; =parser.rs= drops them. Attach
=(file, offset)= to =Atom=, =Term=, =Stmt= in the AST builder. Prerequisite for
the source-location ticket and costs nothing with pest.

** TODO [#B] Tree walker is positional and untested
=parser.rs= is ~60 =into_inner().next().unwrap()= calls plus an =is_kw= filter to
skip keyword tokens. Any grammar edit is a silent panic risk.
*** Fix
Typed builder per rule; grammar tests with pest's =parses_to!=; a corpus of
positive and negative example files run by =cargo test=.

** TODO [#B] Write the grammar spec
=docs/grammar.md=: EBNF, operator precedence, definition of symbol vs variable
vs string, comma rules in blocks, and the example corpus. This is the artifact
that lets the parser be replaced without changing the language.
Precedent: Soufflé keeps a Bison grammar as the reference and documents from it.

** DONE [#B] Case-based variable syntax
DECIDED (E DR-4/DR-5): uppercase variables kept; identifiers [A-Za-z0-9_]; a.b qualified name, X.b field access, .path keypath literal; hyphenated names are strings; - and / always operators; edition 2026 + dform migrate.
Uppercase initial = variable, lowercase = symbol (Prolog convention). Blocks
resource types or keys with a leading capital. Alternatives: sigil for
variables (=$X=), or =let=-style declared variables. Decide with the symbol
ticket.

** TODO [#A] Replace pest with a hand-written lexer and parser
Decision: best in class from the start rather than a pest cleanup pass.
pest error messages ("expected one of [...]") and lack of error recovery are
not good enough for an editor, and the positional tree walker has to be
rewritten anyway to attach spans.
*** Design
- =logos= lexer producing spanned tokens; keywords are token kinds, which
  removes the =KW_TAIL= boundary hack
- hand-written recursive descent for statements, Pratt parser for expressions
- error recovery at statement boundaries (=.=) and block boundaries (=}=) so one
  bad statement yields one diagnostic and parsing continues
- diagnostics via =ariadne= or =codespan-reporting=: labeled spans, notes, hints
- lossless syntax tree (=rowan= or similar) so =dform fmt= and the language
  server share the parser
*** Acceptance
- every parse error names file:line:col and the expected token class
- a file with three independent syntax errors reports all three
- grammar spec (=docs/grammar.md=) and the example corpus are the test suite

** TODO [#A] Plugin protocol: out-of-process gRPC
Provider is any executable. Engine spawns it, handshakes on a local socket,
speaks versioned protobuf. Cloud SDKs live in Go and Python, so the boundary
must be a process, not a library.
*** Methods
| Method    | Capability | Purpose                                              |
|-----------+------------+------------------------------------------------------|
| Handshake | both       | protocol version, capabilities                       |
| Configure | both       | credentials, region, endpoint                        |
| Schema    | both       | types, attributes, computed flags, extern predicates |
| Query     | fact       | bound args in, facts out, streamed                   |
| Read      | resource   | refresh one resource by remote id                    |
| Plan      | resource   | prior + desired in, diff + requires_replace out      |
| Apply     | resource   | execute one planned action, return new state         |
| Import    | resource   | remote id in, address + attrs out                    |
Plan and Apply are per resource. The core owns ordering, parallelism, state
persistence, and crash safety. Supersedes the "provider trait is too thin" ticket.
*** Non-goals
- the protocol never carries rules, only facts and schema. Runtime-injected
  rules would bypass stratification and provenance. Rules ship as source; see
  the provider library ticket.
- no dlopen / dynamic library providers
*** Precedent
Terraform plugin protocol v6 (shape only, not the SDK); Pulumi provider gRPC.

** TODO [#A] Two plugin capabilities: fact provider and resource provider

* Gaps found by assuming the roadmap is finished
Second review pass, 2026-09-27: what a completed board still gets wrong.

** TODO [#A] Secrets and ephemeral values
No ticket covered secrets. Extern results land in the plan file, attributes in
remote state, credentials in provider config, values in plan output.
*** Design
- =secret(V)= value type; taint propagates through every derivation
- never printed, never written to plan or state; stored as a reference to a
  secret store or re-derived at apply
- schema marks sensitive attributes so provider-returned values are tainted
- =ephemeral= externs: results used during apply, never persisted
- in the fact store a secret is a reference token, never bytes; bytes exist
  only inside the provider call, in =zeroize=-backed, =mlock=ed buffers
  (=secrecy= crate). The engine clones values into every derived fact and
  binding, so keeping bytes out of the store is what makes zeroing sufficient.
*** Precedent
Terraform =sensitive= (0.14) and =ephemeral= (1.10), both a decade late.

** TODO [#C] Language editions
Pre-release: no backward compatibility, no migrate tool, no supported
previous edition (decided 2026-09-27). Keep only the one-line =edition 2026.=
pragma so migration is possible after a first release. E DR-17's migration
clauses do not apply. Precedent: Rust editions, later.

** TODO [#A] Apply executor
The protocol ticket says the core owns ordering and parallelism; nothing
specifies it. DAG walk over the plan, parallelism limit, per-action state
persistence, partial failure semantics, retry policy from schema, and resume
from a half-applied plan. Replacement ordering (=create_before_destroy=) and
deposed objects live here.

** TODO [#B] Multi-stack orchestration
The answer to "provider fed by a resource output" is a downstream stack, so
something must run stacks in dependency order with outputs flowing between
them. =dform run-all= over a stack graph declared in facts, or the problem is
pushed to shell scripts.
Precedent: Terragrunt run-all; Terraform Stacks.

** TODO [#B] Provider configuration as facts
Credentials, region, endpoint come from settings, so provider configuration is
derived data. It needs its own stratum before any extern from that provider can
run, and a compile error when it depends on an extern or a =ref=. This is
exactly where Terraform broke.

** TODO [#B] Typed stack inputs
=--set= accepts scalars only, no validation, no input files, no required
inputs, no defaults with types. The interface half of the stacks ticket.

** DONE [#B] Null, absent, and empty in the value model
DECIDED (E DR-6): absent is bottom; null is a schema-gated Flat value; empty set is bottom.
Datalog absence is "no fact"; APIs distinguish unset, null, and empty. =Value=
has no null. Decide: attributes are absent or present, =null= is a value only
where the schema allows it, and empty collections are ordinary values.
Precedent: Terraform optional/default/null semantics, settled over years.

** TODO [#B] External files and templates as externs
=pngu.df= stubs the dashboard JSON because nothing can read a file. A =file=
fact provider (=extern file.json(+path, -value)=, =file.text=, =file.template=)
so templates are facts with provenance and hashing, not a =file()= builtin.

** DONE [#B] Impure values
DECIDED (E DR-7, DR-15): only through externs whose results persist in state; greedy allocate aggregate with pins now, clingo behind a flag later.
Random suffixes, timestamps, generated passwords. Rule: impurity enters only
through an extern whose results are persisted in state, never through a
builtin. A =random= reference provider demonstrates it.
Precedent: Terraform =random_*= provider (correct), =timestamp()= (a mistake).

** TODO [#B] Query and inspection tooling

JSON and table output, and =dform explain= for a plan action. Pairs with the
provenance ticket.

** TODO [#C] Provider supply chain

** TODO [#A] Reactive inputs and controller mode
Datalog is naturally reactive: inputs are relations, and incremental
evaluation recomputes only what depends on a changed input. "Resources as
input" is declaring that a relation is fed by a watch rather than a file.
World facts from refresh are already such a relation.
*** Design
- =input relation= declarations with a source: file, git ref, Kubernetes
  informer, cloud event bus, message queue, file watcher
- continuous mode: subscription to input changes yields a stream of
  deformations, gated by the same policy, applied automatically or held for
  approval; debounce and batching per stack
- drift surfaced as facts so policy can act on it
- operator packaging: a dform program with CRDs as input facts is a
  Kubernetes reconciler; resource provider is the Kubernetes API or a cloud
- admission mode: the same policy packs evaluate a proposed object or a PR's
  plan before it lands
*** Why it matters
Puts dform against Crossplane compositions, which are painful enough that
Crossplane added composition functions to escape YAML patching. Datalog as the
composition language is the better answer. Also Gatekeeper's niche for
admission, with a better language.
*** Depends on
Incremental evaluation, stacks, apply executor, extern binding patterns.
Precedent: Crossplane, Kubernetes controller-runtime, Gatekeeper, differential
dataflow.

"what did this stack look like in March" as a query.
Precedent: Datomic.

* Research directions
State of the art worth exploring. Each names the ticket it feeds and a
maturity note. Not tickets until someone reads the paper and writes one.

** Provenance semirings
Green, Karvounarakis, Tannen 2007. Facts carry semiring elements; derivations
combine them. Why-provenance, counting, cost (tropical), trust, and
information-flow labels are the same engine with a different semiring.
Feeds: =why= query, cost as facts, secrets taint, L1b ownership.
Maturity: mature theory, several implementations. Read first.

** Existential rules and labeled nulls
Datalog±, Vadalog (Oxford, production), Nemo (Rust, 2024). The chase invents
nulls for things known to exist but not yet identified, and reasons over them.
This is "known after apply" in database theory. Alternative to the
reject-at-compile-time rule in the unknown-values DECIDE: refs as labeled
nulls, engine reports which conclusions depend on them.
Feeds: unknown-values DECIDE. Maturity: production systems exist.

** DBSP and differential dataflow
Feldera. Proven incremental semantics over relational queries including
recursion. Foundation for reactive mode; subsumes the semi-naive ticket.
Feeds: reactive inputs, incremental evaluation. Maturity: production.

** Monotonicity types
Datafun (Arntzenius, Krishnaswami). Type system tracks monotone functions;
stratification and incremental safety become type checks.
Feeds: aggregate stratification, extern rules. Maturity: research, small idea.

** Answer set programming and choice
clingo. Derive vs solve: assign non-overlapping CIDRs, place across zones,
minimize cost. A =solve= stratum with choice rules and optimization. Solutions
pinned in state like impure values to keep plans deterministic.
Feeds: new L-ticket if pursued. Maturity: clingo very mature.

** NetKAT and BDD reachability
Foster et al.; Batfish (Datalog + BDDs, production). Symbolic reasoning over
all packets through security groups and route tables.
Feeds: L15 network types. Maturity: mature.

** Automated reasoning at AWS
Zelkova (SMT over IAM), Tiros (network). Precedent for a fact provider that
answers "does this policy grant X" symbolically.
Feeds: fact providers. Maturity: production, closed.

** View update problem and lenses
Classic DB theory; Foster and Pierce lenses. Which base facts must change to
make a target view appear: import, adopt, drift reconciled into source,
automatic =moved= proposals.
Feeds: L7 lifecycle, adopt. Maturity: old theory, no production Datalog does
it; a research contribution if achieved.

** Egglog
Zhang, Willsey 2023. Datalog plus equality saturation. Canonicalization: two
intents equal if the e-graph says so; detect renamed resources as equivalent.
Feeds: L7 =moved= detection, diff. Maturity: speculative for this domain.

** Mangle and Rel
Google Mangle (Datalog with aggregation, functions, types, built for knowledge
about software systems); RelationalAI Rel (lattice-aware relational language).
Closest current systems. Study before committing syntax and stdlib.
Feeds: grammar spec, L9 builtins.

** Information-flow types
Jif, decentralized label model. Secret taint through derivation is IFC; labels
compose as a lattice, which is a semiring instance.
Feeds: secrets. Maturity: mature theory.

** Salsa
rust-analyzer's demand-driven incremental compilation framework. For the
compiler and language server, not the engine.
Feeds: language server, parser rewrite. Maturity: production.

* Lessons from prior art
Terraform mistakes and how alternatives avoided them. Referenced by tickets.

** State as truth instead of cache
Full attribute copies in state bred drift, corruption, and state surgery.
Secrets sat in plaintext for a decade. CloudFormation, ARM/Bicep, Crossplane
have the platform own state; System Initiative has no state file at all.
Applies to: stacks ticket, refresh ticket. Keep =state.json= as identity
mapping only; compare attributes from refresh; encrypt at rest (OpenTofu did,
Terraform never).

** Monolithic state, then Terragrunt
No native stack splitting or cross-stack wiring for a decade; Terraform Stacks
arrived 2024. Applies to: L6 stacks. Cross-stack references native and typed.

** Data sources refreshed every plan
Slow plans; plan could differ from apply. Applies to: extern ticket. Extern
results recorded in the plan file.

** Unknown values never a language concept
"for_each value depends on resource attributes that cannot be determined until
apply." Discovered at runtime by users. Applies to: unknown-values DECIDE.
Reject statically.

** Types came late and broke everything
0.11 to 0.12 rewrite. Bicep shipped typed from the start. Applies to: L1, L8.

** Refactoring was destroy and recreate for years
=moved= 1.1, =import= block 1.5, =removed= 1.7. Applies to: L7 lifecycle.
First-class from the beginning.

** Sets diffed as positional lists
Unreadable plans for rules and statements. Already reproduced in the prod
plan. Applies to: ordered lists ticket, plan output ticket.

** Static-only corners of the language
Backend and provider blocks could not use variables. OpenTofu fixed it.
Applies to: stacks, provider declaration. No statement is second class;
these evaluate in stratum zero.

** depends_on and dynamic blocks
Escape hatches for what HCL could not express. Datalog does not need them.
Do not add them.

** Providers inside modules
Module-owned provider config blocks destroy; provider fed by a resource output
fails at plan. Rule: providers configured at stack root, modules pure,
dependent providers live in a downstream stack. Applies to: L4, L6.

** Provider SDK before protocol
SDKv2 lacked types and nulls; framework rewrite took years. Pulumi bridged
Terraform providers and inherited every limitation. Applies to: plugin
protocol ticket. Protocol and schema-as-data are the contract.

** No native tests until 1.6
Applies to: L12, fake provider as conformance harness.

** License
BSL produced OpenTofu overnight. Decide once.

** Alternatives, one line each
- Pulumi: general-purpose languages bought expressiveness with nondeterminism
  and hard testing. Constrained language is a feature.
- CDK / CDKTF: transpiling to another IaC layer means debugging two layers.
- CloudFormation: server-side state is right; rollback rarely worked.
- Crossplane: reconciliation without preview. A controller mode for dform can
  coexist with plan since a plan is the diff a reconciler would apply.
- CUE: the lattice. See attribute-assembly DECIDE.
- System Initiative: infra as queryable model with change sets. Closest
  relative to "config is a database".
- Bicep: typed diagnostics and no state file when the platform cooperates.
- Winglang and cloud-agnostic layers: abstraction over clouds leaks. Keep
  provider types provider-shaped.
